## Spacing Scale

Multiples of 4 only. Carried forward from Phases 2–4.

| Token | Value | Usage in Phase 5 |
|-------|-------|------------------|

| sm | 8px (`gap-2`, `p-2`) | Tooltip internal padding (horizontal + vertical); gap between tooltip sections |

| 2xl | 48px | Not used in Phase 5 new elements |
| 3xl | 64px | Not used in Phase 5 new elements |

**Exceptions (all multiples of 4):**

- **Badge strip height:** `auto` — content drives height. Bottom-edge strip uses `padding: 4px 4px` (`p-1`, the `xs` token). Both vertical and horizontal padding are 4px — a multiple of 4.

- **Tooltip z-index:** `z-index: 50` — above all page content; below no existing layering. Not a spacing value; documented here for executor clarity.
- **Tooltip offset from portrait:** 8px (`translateY(calc(-100% - 8px))` above, or `translateY(8px)` below). Matches the `sm` spacing token.

## Component Inventory

Phase 5 modifies `DraftPortrait` and adds one new component `IntelTooltip`. No existing component is structurally changed — only props and conditional children are added.

### Modified: `<DraftPortrait>`

**New props:**

```tsx
interface DraftPortraitProps {
  kind: 'pick' | 'ban'
  heroId?: number
  isActive?: boolean
  ordinal?: string
  // Phase 5 additions:
  heroStats?: { winRate: number; pickRate: number }  // from useHeroStats()
  playerIntel?: {                                      // from useMatchIntel()
    playerName: string
    games: number | null          // null = hidden profile
    winRate: number | null        // null = hidden profile
    heroName: string
    counters: CounterHero[]
  }
}

interface CounterHero {
  heroId: number
  heroName: string
  knownPlayers: string[]   // names of opposing players who meet D-09 threshold; [] = none
}
```

**Badge strip (DRAFT-03):**

- Rendered only when `kind === 'pick'` AND `heroId` is defined AND `heroStats` is defined.
- Not rendered on bans. Not rendered on empty slots.
- Position: `absolute; bottom: 0; left: 0; right: 0`.
- Background: `rgba(0,0,0,0.72)` — translucent scrim over portrait bottom edge.
- Content: `{winRate%} · {pickRate%}` — e.g. `52% · 18%`.
- Text alignment: `text-align: center`.
- Padding: `4px 4px` (`p-1`, the `xs` spacing token).
- Font: 10px, weight 400, `font-variant-numeric: tabular-nums`.
- Winrate value color: threshold rule from Color section. Separator `·` and pickrate: `#888888`.
- `aria-hidden="true"` — decorative; full stat data is available via tooltip.

**Tooltip trigger:**

- Rendered only when `kind === 'pick'` AND `heroId` is defined AND `playerIntel` is defined.
- `onMouseEnter` → show `<IntelTooltip>` (via state flag or conditional render).
- `onMouseLeave` → hide tooltip.
- Cursor: `cursor-default` — the portrait is still not a link or button; hover is informational.
- No `onClick` — tooltip is hover-only, no click-to-pin behavior.
- Portrait does NOT dim or gain a focus ring on hover — visual change is only the tooltip appearing.

### New: `<IntelTooltip>`

Positioned floating card that appears above or below a DraftPortrait on hover.

**Positioning logic:**

- Default position: above the portrait (`bottom: calc(100% + 8px); left: 50%; transform: translateX(-50%)`).
- Viewport check: if the portrait's `getBoundingClientRect().top < 180` (less than ~180px from viewport top, leaving no room for the card above), flip to below: `top: calc(100% + 8px); left: 50%; transform: translateX(-50%)`.
- 180px threshold accommodates a tooltip card of ~160px max-height with 8px gap. Use `useRef` + `getBoundingClientRect` on mount to determine flip direction.
- Z-index: 50.
- Position: `absolute` within the `relative` DraftPortrait wrapper.

**Card dimensions:**

- Width: `min-w-[160px] max-w-[220px]` — content-driven width, capped to prevent overflow on small viewports.
- Height: `auto` — content-driven.
- No explicit max-height; the 3-counter limit + 2-line player section keeps the card short.

**Card visual spec:**

```
background:  #111111
border:      1px solid #1a1a1a
border-radius: 4px
padding:     8px
box-shadow:  0 4px 16px rgba(0,0,0,0.6)
```

**Card layout (top to bottom):**

```
┌─────────────────────────────────┐
│  {PlayerName}          10px 700 │  ← player name, truncated if long, color #d8d8d8
│  {N} games · {W}% on {HeroName} │  ← stat line, 10px 400, #888888; "— games · — %" for hidden
├─────────────────────────────────┤  ← 1px separator #1a1a1a, margin 6px top/bottom
│  COUNTERS              10px 700 │  ← section label, #444444, uppercase
│                                 │
│  [32px portrait] HeroName       │  ← counter row ×3 (top-3 only)
│  [32px portrait] HeroName       │     hero name: 10px 400 #d8d8d8
│  [32px portrait] HeroName ⚠ P  │     ⚠: #ef4444, player name: 10px 400 #888888
└─────────────────────────────────┘
```

Legend: `P` = opposing player name (e.g. `Miracle-`), truncated to 12 chars with ellipsis.

**Loading state (while `useMatchIntel` is in flight):**

Show the player name only (if already available from match payload) with a skeleton placeholder for the stat line and counter rows:

```
┌─────────────────────────────────┐
│  {PlayerName}                   │
│  Loading...               10px  │  ← #444444, not animated — no spinner
│                                 │
│  COUNTERS                       │
│  [32px grey box] ─────────      │  ← grey placeholder rect, no animation
│  [32px grey box] ─────────      │
│  [32px grey box] ─────────      │
└─────────────────────────────────┘
```

- Grey placeholder rects: `#1a1a1a`, rounded-sm, matching the portrait size and a text-width placeholder.
- No `animate-pulse` — avoid motion noise on a data-dense screen. Static placeholders are sufficient.

**Error state:**

`useMatchIntel` returns null or throws → tooltip does NOT render. The badge strip, if stats were already loaded via `useHeroStats`, continues to show. No error message in the tooltip — simply no tooltip appears. This matches the Phase 4 pattern of silent failure for non-critical overlay data.

## Loading States

| State | What renders |
|-------|-------------|
| `useHeroStats` not yet resolved | Badge strip hidden (condition: `heroStats` prop undefined). Portrait renders normally. No skeleton on badge. |
| `useHeroStats` resolved | Badge strip appears on all pick slots with `heroId`. |
| `useMatchIntel` not yet resolved | Tooltip shows player name + static loading skeleton (see above) on hover. |
| `useMatchIntel` resolved | Full tooltip with stat line + 3 counter rows on hover. |
| `useMatchIntel` error (network / 502) | Tooltip does not render. Badge continues to show if `heroStats` is available. |
| Hidden profile (account_id = 4294967295) | Tooltip stat line shows `— games · —%` instead of numbers. Counter rows still show (counterpick data is hero-based, not player-based). |
| No counters returned for a hero | Tooltip renders player section only; `COUNTERS` section is hidden (no empty-state copy shown). |
| `knownPlayers` is empty for all counters | Counters render without any `⚠` flag. |

## Interaction Contract

### Hover Behavior

- **Trigger:** `onMouseEnter` on the DraftPortrait outer wrapper.
- **Dismiss:** `onMouseLeave` on the same wrapper. No click-to-pin. No ESC key handler (Phase 7 accessibility hardening is out of scope for Phase 5).
- **Transition:** Tooltip appears and disappears immediately (no CSS fade). Adding a fade introduces complexity for an analytics tool where users prefer instant data.
- **No debounce** on hover enter — show immediately. If the user moves quickly across multiple portraits, each tooltip shows in sequence without delay.
- **Only pick portraits** trigger the tooltip. Ban portraits and empty slots: no hover behavior.

### Polling Integration

- `useHeroStats()` — no polling. `refetchInterval: false`. Hero stat data is valid for 6h (matches BFF TTL). TanStack Query stale-while-revalidate handles background refresh on next page mount.
- `useMatchIntel(matchId)` — polling cadence mirrors `useDraftDetail`: dynamic callback `(q) => q.state.data?.game_state === 2 ? 5_000 : false`. Player hero histories are stable during a match; the 5s cadence is sufficient for the "known to play" freshness requirement. The BFF caches by `match_id` (TTL 15min) so rapid re-fetches hit cache.
- Both hooks compose on `MatchPage` (or `DraftSection`) via TanStack Query. No cross-contamination with `useMatchDetail`.

### State Transitions

| Transition | Visual behaviour |
|-----------|-----------------|
| Draft pick confirmed → `heroStats` already loaded | Badge strip appears on the new portrait on the next render. No animation — strip just appears. |
| Draft pick confirmed → `heroStats` not yet loaded | Portrait appears without badge; badge appears on next successful `useHeroStats` poll (or on mount if cache is warm). |
| Player hovers a pick portrait | Tooltip card renders above (or below if near viewport top). Immediate — no delay. |
| Player moves mouse off portrait | Tooltip card un-mounts. Immediate. |
| Match transitions from draft (game_state 2) to in-game (game_state 5) | Badges remain visible. Tooltips remain triggerable (pick positions are frozen). `useMatchIntel` stops polling (dynamic `refetchInterval` returns `false`). |

## Copywriting Contract

Every copy string that can appear in Phase 5 UI elements is declared here.

| Element | Copy |
|---------|------|
| Badge strip — format | `{winRate}% · {pickRate}%` e.g. `52% · 18%` |
| Badge strip — hidden (no data) | (no text — strip hidden entirely) |
| Tooltip — player name | Valve-provided player name string (no transformation) |
| Tooltip — stat line (normal) | `{N} games · {W}% on {HeroName}` e.g. `143 games · 57% on Anti-Mage` |
| Tooltip — stat line (hidden profile) | `— games · —% on {HeroName}` |
| Tooltip — loading stat line | `Loading...` (10px, `#444444`) |
| Tooltip — section label | `Counters` (all-caps via CSS `text-transform: uppercase`) |
| Tooltip — counter row (no known player) | `{HeroName}` |
| Tooltip — counter row (known player) | `{HeroName} ⚠ {PlayerName}` — space before `⚠`, space after |
| Tooltip — no counters | (section hidden — no empty-state copy) |
| Tooltip — error state | (tooltip does not render — no error copy) |

**Copy style rules:**

- Em dash `—` (U+2014) for the hidden-profile stat placeholder — matches the established Phase 3 player-row convention (`isDraftSlot ? '—'`).
- Middle dot separator `·` (U+00B7) in both badge format and tooltip stat line — consistent with the badge spec in CONTEXT.md.
- `⚠` is U+26A0 (WARNING SIGN) — rendered as plain Unicode text character, `font-size: 10px`, `color: #ef4444`. No SVG icon.
- Player names truncated to 12 characters with `…` (U+2026) if longer. Applied via CSS `overflow: hidden; text-overflow: ellipsis; white-space: nowrap; max-width: 80px` on the player name span inside counter rows.
- `Counters` section label renders as `COUNTERS` via `text-transform: uppercase` — not hardcoded as uppercase in JSX. Rationale: consistent with turn indicator and column label patterns from Phase 4.
- `Loading...` is sentence-case with trailing ellipsis. Three dots (U+002E ×3), not the ellipsis glyph U+2026 — matches the visual weight of the trailing text.

**No primary CTA** — Phase 5 is observational (tooltip is informational, no action).
**No destructive actions** — read-only phase.

## Accessibility Notes

Desktop-first per REQUIREMENTS.md. Minimum accessibility practice for Phase 5 elements:

- Badge strip: `aria-hidden="true"` — it is decorative; full stat data is available via tooltip.
- Tooltip: not keyboard-accessible in Phase 5. Phase 7 hardening may add `aria-describedby` or `role="tooltip"`. For now, the tooltip renders on mouse hover only, which is acceptable for a desktop analytics tool used by a small group.
- `⚠` flag: rendered as a text character with surrounding visible player name. Screen readers will announce the warning sign + player name inline. Acceptable.
- Counterpick portrait images: `alt={heroName}` — descriptive alt on each mini-portrait.
