export interface HistorySample { t: number; gold: number; xp: number }

**Pure `buildSample` (D-07, D-08, D-15, D-16, D-18):**
- Signature accepts the parsed Valve live game shape (loose: `{game_state?, duration?, scoreboard?: {duration?, radiant?:{players?: Array<{net_worth?, xpm?}>}, dire?:{players?: ...}}}`).
- Returns `null` when `game_state !== 5`.
- Resolves `const duration = game.scoreboard?.duration ?? game.duration ?? 0`. Returns `null` when `duration === 0`.
- Returns `null` when either team's `players` array is empty/missing (cannot aggregate).
- `sumNw(players)` = `players.reduce((s, p) => s + (p.net_worth ?? 0), 0)`.
- `teamXp(players)` = `players.reduce((s, p) => s + ((p.xpm ?? 0) * duration / 60), 0)` — D-18: missing xpm contributes 0, never throws.
- Returns `{ t: Math.floor(duration), gold: sumNw(r) - sumNw(d), xp: Math.round(teamXp(r) - teamXp(d)) }`.

**`tryWriteSample(matchId, sample)` (D-06, D-09, D-10, D-11, D-12):**
- If `!redis` → return `false`.
- Wrap in try/catch:
  - `const acquired = await redis.set(gateKey(matchId), '1', 'EX', SAMPLE_GATE_SECONDS, 'NX')` — ioredis 5-arg form. Return `false` if `acquired !== 'OK'`.
  - `await redis.rpush(k, JSON.stringify(sample))` then `await redis.ltrim(k, -TIMESERIES_LIMIT, -1)` then `await redis.expire(k, TTL_SECONDS)`. Return `true`.
- catch → `logger.error({ matchId, err: (err as Error).message }, 'history write failed')`; return `false` (D-09 fire-and-forget).

**`readHistory(matchId)` (D-10):**
- If `!redis` → return `[]`.
- try: `const raw = await redis.lrange(tsKey(matchId), 0, -1)`; return `raw.map(s => JSON.parse(s) as HistorySample)`.
- catch → log via `logger.error`, return `[]`.

**`deleteHistory(matchId)` (D-13):**
- If `!redis` → return.
- try: `await redis.del(tsKey(matchId), gateKey(matchId))`.
- catch → log via `logger.error`.

**No I/O outside the three wrappers. No upstream Valve calls. No imports from `../routes/*`.**

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Valve API → BFF | Untrusted external — `match_id` strings flow into Redis key construction; `players[]`/`xpm`/`net_worth` flow into aggregation math |
| BFF → Redis | Persistent state with quotas; ungated writes risk OOM |

## STRIDE Threat Register

| Threat ID | Category | Component | Description | Severity | Mitigation Plan | Residual Risk |
|-----------|----------|-----------|-------------|----------|-----------------|---------------|
| T-10-01 | Tampering | `tsKey(matchId)` | Non-numeric `match_id` could escape colon-delimited key shape (Redis key injection) | low | Caller (Plan 02) gates on `typeof g.match_id === 'number'` before invoking; this module's signatures are typed `matchId: number` and TypeScript strict mode prevents string passthrough | accept (typed boundary) |
| T-10-02 | Denial of Service | `tryWriteSample` RPUSH | Unbounded list growth on a hung match would exhaust Redis memory | medium | D-11 LTRIM 0 -240 caps list to 240 entries; D-12 EXPIRE 7200s caps temporal lifetime; D-06 NX 5s gate caps write rate to 0.2 Hz per match | mitigate (240 entries × ~50 bytes ≈ 12KB/match worst case) |
| T-10-03 | Denial of Service | Distinct `match_id` flood | A flood of distinct match IDs could fill Redis with stale time-series | medium | Only `match_id`s observed in `/api/live/games` (Valve-curated pro tournament feed) reach this code path; D-12 7200s TTL caps lifetime; D-13 explicit DEL on `game_state === 6` accelerates cleanup | accept (Valve curates input set) |
| T-10-04 | Information Disclosure | `JSON.parse` in `readHistory` | A poisoned list entry (manual Redis write) could throw on parse and leak stack via response | low | All parses inside try/catch; on throw, returns `[]` and logs server-side only via pino (D-09); error string never propagates to HTTP response | mitigate |
| T-10-05 | Repudiation | Sampler write failures | Silent failure (D-09 fire-and-forget) makes debugging hard | low | All catch blocks emit `logger.error({ matchId, err })` to pino structured logs | accept (write failure is non-critical) |
| T-10-06 | Tampering | `buildSample` math | Malformed `xpm`/`net_worth` (NaN, negative, huge) flows directly into client chart | low | `(p.xpm ?? 0)` and `(p.net_worth ?? 0)` coerce missing values to 0; Math.round on xp prevents Infinity propagation; chart self-clamps Y axis. Numeric NaN from Valve would render as broken pixel but not crash | accept (rare; chart tolerates) |
</threat_model>
