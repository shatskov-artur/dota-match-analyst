<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser (Vercel origin) → BFF (Railway origin) | Cross-origin requests; CORS gates which origin may call /api/*. |
| Public internet → SPA static host | Anyone can request any path; the SPA rewrite must only serve static index.html, never server logic. |
| Deploy secrets → committed repo | Env files in the repo must be examples only; real secrets live in Railway/Vercel dashboards. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11-08 | Spoofing / Information Disclosure | CORS misconfig (`*`+credentials or wildcard origin) (index.ts) | mitigate | Exact Vercel origin via `env.CORS_ORIGIN`; `credentials` stays false; scoped to `/api/*`; no trailing slash (Pitfall 5); origin read from env so no code change per URL |
| T-11-09 | Tampering | SPA rewrite abuse / open redirect (vercel.json) | mitigate | Rewrite only serves static `/index.html`; no server-side redirect logic; cleanUrls NOT enabled |
| T-11-10 | Information Disclosure | secrets committed to repo (.env.production.example, .env.example) | mitigate | Only `*.example` templates with placeholder values are committed; real secrets set exclusively in Railway/Vercel dashboards; DEPLOY.md instructs dashboard-only secret entry |
| T-11-11 | Information Disclosure | API key in Vite client bundle | accept | Only `VITE_API_URL` (a public URL, not a secret) is exposed to the client; all real keys stay server-side in Railway env. VITE_* inlining is intentional and carries no secret. |
</threat_model>
