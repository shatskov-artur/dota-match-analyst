**Gradient construction (per CONTEXT.md §D-05 and §Specifics):**

```css
background: linear-gradient(
  to right,
  #4ade80 0%,
  #4ade80 {radiantPct}%,
  #ef4444 {radiantPct}%,
  #ef4444 100%
);
```

Hard color stop at `{radiantPct}%` — no blend zone. The bar reads as two solid colors meeting at the probability boundary, so the user can read the numeric position even peripherally. Smooth `transition: width 500ms ease` is applied to the inner Radiant fill div if implemented as two divs (alternative implementation to the gradient stops above — Claude's discretion).

## Component Inventory

Phase 6 adds **one new component** and **modifies one existing component** (insertion only — no internal restructure).

### New: `<WinProbBar>`

```tsx
interface WinProbBarProps {
  /** Stratz radiant win probability ∈ [0, 1]; null = hide entire component */
  radiantWinProb: number | null
  /** Current in-game time in seconds; bar hidden when game_time <= 300 */
  gameTime: number | undefined
  /** Game state from useMatchDetail; bar visible only when game_state === 5 */
  gameState: number | undefined
}
```

**Render gates (per CONTEXT.md §D-06):**

- `gameState === 5` AND `gameTime > 300` AND `radiantWinProb !== null` → render bar.
- Any condition false → return `null`. No placeholder, no error message, no skeleton.

**Computed values:**

- `radiantPct = Math.round(radiantWinProb * 100)` — integer percentage for display and gradient stop.
- `direPct = 100 - radiantPct` — derived; never independently rendered to avoid drift.

**Visual structure (top to bottom inside the component's outer wrapper):**

```
┌──────────────────────────────────────────────────────────────┐  ← outer div, padding 16px top + 16px bottom
│                                                              │
│  68%        ████████████░░░░░░░░░░░░░░░░░          32%      │  ← bar row (flex)
│  [12 700]   [bar 8px tall, full width minus label gutters]   │
│                                                              │
│             RADIANT                              DIRE        │  ← team labels row (flex)
│             [10 700 #4ade80 uppercase]      [10 700 #ef4444] │
│                                                              │
└──────────────────────────────────────────────────────────────┘
                  ↓ 1px hairline #1a1a1a (matches ScoreHeader divider)
```

**Layout (flex):**

- Outer wrapper: `<div className="py-4" style={{ borderBottom: '1px solid #1a1a1a' }}>`.
- Bar row: `<div className="flex items-center gap-4">` — three children: left % label, bar fill (flex-1), right % label.
- Bar fill: `<div className="relative flex-1 h-2 rounded-[4px] overflow-hidden" style={{ backgroundColor: '#0f0f0f' }}>` containing the gradient (or two stacked divs for animatable transition).
- Team labels row: `<div className="flex justify-between mt-2 px-[40px]">` (px matches the % label width so RADIANT aligns under the left edge of the bar and DIRE aligns under the right edge).

**Animation:**

- The Radiant fill width animates with `transition: width 500ms ease` whenever `radiantWinProb` changes.
- The numeric `%` label values do NOT animate (no count-up / tween). They snap to the new integer immediately. Rationale: 30s polling cadence — animating digits between two distant samples implies smooth in-game change which is misleading.

**Accessibility:**

- `role="progressbar"`, `aria-valuemin={0}`, `aria-valuemax={100}`, `aria-valuenow={radiantPct}`, `aria-label={"Radiant win probability"}`.
- Color is not the only signal — numeric % labels carry the same information for users with color-vision deficiency.

### Modified: `<MatchPage>`

**Insertion point:** between `<ScoreHeader />` and the next section.

```tsx
<ScoreHeader match={match} />
<WinProbBar
  radiantWinProb={winProb}
  gameTime={match.game_time}
  gameState={match.game_state}
/>
{match.game_state === 2
  ? <DraftSection ... />
  : <HeroPlayerGrid ... />}
```

The component returns `null` when gates are not met → it occupies zero vertical space when hidden. No conditional wrapper is required at the `MatchPage` level.

**No other Phase 6 components.** The Stratz counterpick upgrade is server-only (`stratzApi.ts` + route swap); the existing `<IntelTooltip>` from Phase 5 keeps the same prop shape and visual layout.

## Loading States

| State | What renders |
|-------|-------------|
| `useWinProbability` not yet resolved (initial fetch in flight) | Bar hidden — return `null`. No skeleton shown. The match screen has many other elements; an 8px bar appearing 1s late is invisible. Skeletons would imply persistence the data may not have. |
| `useWinProbability` resolved with `radiantWinProb !== null` AND gates pass | Full bar renders. |
| `useWinProbability` resolved with `radiantWinProb === null` (Stratz down / 429 / 5xx) | Bar hidden — return `null`. **No** error toast, **no** error inline copy, **no** retry button. |
| `gameTime <= 300` (early-game gate) | Bar hidden — return `null`. No "Available at 5:00" message. The user sees nothing where the bar will be. |
| `gameState === 6` (post-game) | Bar hidden — return `null`. Polling stops (per CLAUDE.md pitfall: polling halts on `game_state === 6`). |
| `gameState === 2` (draft, before in-game) | Bar hidden — return `null`. |
| Probability shifts (e.g. 68% → 71%) | Existing bar animates fill width over 500ms ease; numeric labels snap immediately. |

The "silent disappearance" rule from CONTEXT.md §D-13 governs every non-render path: **no placeholder, no error, no copy.**

## Interaction Contract

### Polling Integration

- `useWinProbability(matchId)` — TanStack Query v5 hook. `staleTime: 0`, `refetchInterval: (query) => query.state.data?.gameState === 5 && (query.state.data?.gameTime ?? 0) > 300 ? 30_000 : false` — polls every 30s while in-game past 5min, off otherwise. Stops automatically on `game_state === 6`.
- The hook MAY be merged into `useMatchDetail` (CONTEXT.md §D-15 leaves this to Claude's discretion). If merged, the existing 30s in-game cadence applies; if separate, the cadence above applies. Either way the cadence is 30s.
- Counterpick matchup data (Stratz `heroVsHeroMatchup`) does NOT poll — `staleTime: Infinity`, `refetchInterval: false`. 6h server cache TTL (CONTEXT.md §D-11).

### State Transitions

| Transition | Visual behaviour |
|------------|-----------------|
| Match enters `game_state === 5`, `game_time` crosses 300 | Bar appears on the next 30s tick. No animation on appearance — bar simply renders at its initial probability. |
| Probability changes mid-game (e.g. 68% → 71%) | Bar fill animates width 500ms ease. Numeric labels update immediately (snap). |
| Stratz returns null after previously returning a number | Bar disappears (un-mounts) on the next render. No fade. |
| Stratz returns a number after previously returning null | Bar appears on the next render at its current probability. No fade. |
| `game_state === 6` | Bar disappears (un-mounts). Polling halts. Permanent for this match view. |
| User navigates away and back | TanStack cache may still hold a value (5min default `gcTime`). Bar re-appears immediately if cache valid; otherwise fetches fresh. |

### Hover / Click

- The bar is **non-interactive**. No hover state, no click handler, no tooltip. The numeric % labels carry the only data the user needs.
- No focus ring (the bar is `role="progressbar"`, not `role="button"`).

## Copywriting Contract

Every copy string that can appear in Phase 6 UI is declared here.

| Element | Copy |
|---------|------|
| Left percentage label | `{radiantPct}%` — e.g. `68%`. Integer only, no decimal. |
| Right percentage label | `{direPct}%` — e.g. `32%`. Integer only, no decimal. `direPct = 100 - radiantPct`. |
| Left team label | `RADIANT` (uppercase, hardcoded — Stratz win probability is always Radiant-vs-Dire regardless of the actual `radiant_team.team_name`) |
| Right team label | `DIRE` (uppercase, hardcoded) |
| Bar hidden — pre-5min | (no copy — component returns null) |
| Bar hidden — Stratz unavailable | (no copy — component returns null) |
| Bar hidden — post-game | (no copy — component returns null) |
| Bar hidden — draft phase | (no copy — component returns null) |
| ARIA label | `Radiant win probability` (lowercase except R, sentence-case for screen readers) |

**Copy style rules:**

- `RADIANT` and `DIRE` are uppercased via CSS `text-transform: uppercase` (or `uppercase` Tailwind class) — NOT hardcoded as uppercase string in JSX. Rationale: matches `ScoreHeader` team-label pattern.
- `%` glyph is U+0025 (PERCENT SIGN), no space between number and percent: `68%` not `68 %`.
- Percentages always integer. `Math.round` from a `[0,1]` float. No "approximately" wording.
- The bar deliberately has **no title, no caption, no helper text**. Position immediately under `ScoreHeader` makes its meaning self-evident in context. Adding a "Win Probability" header would compete with the dense info already on the screen.
- **No** "Powered by Stratz" attribution in v1. Stratz ToS does not require it for non-commercial use; if v2 commercializes, attribution moves into the Phase 7 footer.

**No primary CTA** — Phase 6 is read-only observational.
**No empty state copy** — the empty state IS the absence of the component.
**No error state copy** — graceful degradation per CONTEXT.md §D-13 means silence.
**No destructive actions** — read-only phase.

## Accessibility Notes

Desktop-first per REQUIREMENTS.md. Minimum accessibility for Phase 6:

- `role="progressbar"` with `aria-valuenow`, `aria-valuemin=0`, `aria-valuemax=100` so screen readers announce the probability.
- `aria-label="Radiant win probability"` — explicit because team labels (`RADIANT` / `DIRE`) are below the bar, not labelling it directly.
- Color is not the only signal — numeric % labels carry the same information for color-vision-deficient users.
- The 500ms width animation respects `prefers-reduced-motion: reduce` → set `transition: none` when the media query matches. Implementation: inline `style={{ transition: prefersReducedMotion ? 'none' : 'width 500ms ease' }}` or a CSS rule.
- No keyboard interaction needed — bar is non-interactive.
