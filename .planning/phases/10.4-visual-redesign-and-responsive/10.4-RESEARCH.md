# Phase 10.4: Visual redesign and responsive - Research

**Researched:** 2026-06-06
**Domain:** Tailwind CSS 4 CSS-first theming (`@theme` tokens) + responsive reflow of an existing React 19 / Vite 6 data-viz app
**Confidence:** HIGH (stack, token mechanics, breakpoints, migration surface all verified against installed code + current docs)

## Summary

This is a **restyle + responsive** phase, not a feature phase. The information architecture (Phase 10.3 three-row Match layout, Home league-accordion stack) is LOCKED and carries over unchanged. Two jobs: (1) **UI-01** — replace ~264 hardcoded color/style literals scattered across 21 component/page files with a shared Tailwind 4 `@theme` token layer holding the "Tactical Slate" palette; (2) **UI-02/UI-03** — make every screen reflow cleanly across phone (375), tablet (768), laptop (1280), desktop (1536+) with no horizontal scroll, overlap, or clipping.

The stack is already in place and correct: Tailwind **4.2.4** via `@tailwindcss/vite` 4.2.4 (verified in `client/package.json` + `node_modules`), CSS-first config in `client/src/index.css` (which today declares only two `@theme` color tokens — `--color-radiant: #4ade80`, `--color-dire: #ef4444`). The canonical Tactical Slate token set already exists at `.planning/sketches/themes/tactical-slate.css` (~30 tokens) and an APPROVED design contract exists at `10.4-UI-SPEC.md`. The work is mechanical and well-specified; the risk is breadth (21 files, three distinct literal-bearing styles) and one test that hard-asserts the old hex values.

**Primary recommendation:** Declare the full Tactical Slate palette/fonts/radii/shadows/tracking in `@theme` inside `index.css` (Tailwind 4 auto-generates `bg-*`/`text-*`/`border-*` utilities AND exposes every token as a runtime `var(--…)` for SVG `fill`/`stroke`/gradients). Migrate components file-by-file: arbitrary-value classes (`text-[#d8d8d8]`) → token utilities (`text-text`), inline `style={{ color: '#…' }}` → token utility or `var(--…)`, and JS `onMouseEnter` hover handlers → CSS `:hover`/`group-hover` utilities. Adopt the UI-SPEC's single canonical stack breakpoint (`max-width: 1180px`) implemented as Tailwind responsive utilities. **Fix `HistoryGraphs.test.tsx` first** (Wave 0) — it asserts `fill === '#4ade80'`/`'#ef4444'`, the exact literals being retired, and WILL go red.

### Pattern 1: Full `@theme` token block (UI-01 core)
**What:** Declare every Tactical Slate token under `@theme` so Tailwind both generates utilities AND emits runtime `:root` vars.
**When:** Once, in `index.css`, before any component migration.
**Example:**
```css
/* Source: tailwindcss.com/docs/theme + tactical-slate.css values */
@import "tailwindcss";

@theme {
  /* colors → generate bg-*, text-*, border-*, fill-* utilities + runtime vars */
  --color-bg: #14151a;
  --color-bg-elev: #181a20;
  --color-surface: #1d1f27;
  --color-surface-2: #23262f;
  --color-border: #2b2e38;
  --color-border-glow: #3a3e4a;
  --color-text: #e6e7ea;
  --color-text-muted: #9aa0ad;
  --color-text-dim: #646b78;
  --color-primary: #d4a24a;        /* muted gold */
  --color-accent: #5b9bd5;         /* steel blue */
  --color-radiant: #6bcf8a;        /* softened from #4ade80 */
  --color-dire: #e06a72;           /* softened from #ef4444 */
  --color-gold: #d4a24a;
  --color-danger: #e06a72;

  /* fonts → generate font-sans / font-mono utilities + runtime vars */
  --font-sans: 'Inter', system-ui, sans-serif;
  --font-mono: 'JetBrains Mono', ui-monospace, monospace;

  /* radii → rounded-sm/md/lg/full */
  --radius-sm: 6px;
  --radius-md: 10px;
  --radius-lg: 16px;

  /* shadows → shadow-card */
  --shadow-card: 0 6px 20px rgba(0,0,0,0.35);

  /* tracking → tracking-label */
  --tracking-label: 0.14em;
}

/* values that should NOT generate utilities (gradients, soft tints used only via var()) */
:root {
  --color-primary-soft: rgba(212,162,74,0.12);
  --color-accent-soft: rgba(91,155,213,0.12);
  --color-radiant-soft: rgba(107,207,138,0.12);
  --color-dire-soft: rgba(224,106,114,0.12);
  --card-bg-grad: linear-gradient(180deg, #20232c 0%, #1a1c23 100%);
  --glow-primary: 0 0 0 1px rgba(212,162,74,0.30);
  --glow-accent: 0 0 0 1px rgba(91,155,213,0.30);
}
```
Then in TSX: `className="bg-bg text-text border-border rounded-lg shadow-card font-mono tracking-label"`.

### Pattern 2: Three literal migration shapes
The 264 literals come in **three distinct forms** (verified by reading the components). Each migrates differently:

1. **Arbitrary-value utility classes** — `text-[#d8d8d8]`, `border-[#1a1a1a]`, `bg-gray-950`, `text-green-400`, `text-[11px]`, `tracking-[0.25em]`
   → token utility: `text-text`, `border-border`, `bg-bg`, `text-primary`. Off-grid sizes either become `--text-*`/`--tracking-*` tokens or stay as documented arbitrary values for fixed glyphs.

2. **Inline `style={{ … }}` objects** — `style={{ background: '#0a0a0a', color: '#d8d8d8' }}` (MatchPage), `style={{ color: '#4ade80' }}` (ScoreHeader)
   → prefer moving to className token utilities; if it must stay inline (computed/gradient), use `var(--…)`: `style={{ background: 'var(--card-bg-grad)' }}`.

3. **JS-const literals fed to SVG/dynamic attrs** — `const RADIANT_GREEN = '#4ade80'` (HistoryGraphs), `fill={team==='radiant' ? '#4ade80' : '#ef4444'}` (DotaMapView), `goldDiff.color` (ScoreHeader)
   → reference runtime var: `const RADIANT = 'var(--color-radiant)'`, `fill="var(--color-radiant)"`. **This automatically picks up the softened values** — and is exactly why the test in §Pitfall 1 must change.

### Pattern 3: Replace imperative JS hover with CSS state utilities
**What:** Five components set `.style.background`/`.style.color` in `onMouseEnter`/`onMouseLeave` (MatchPage back-link, MatchRow, PlayerRow, ItemsBlock, CooldownsBlock).
**Why:** UI-SPEC Interaction Contract specifies CSS hover (`row bg → --color-surface-2`, 120-160ms). Imperative handlers hardcode hex and bypass tokens.
**Example:**
```tsx
// before: onMouseEnter={e => (e.currentTarget.style.background = '#0f0f0f')}
// after:
<div className="transition-colors duration-150 hover:bg-surface-2">…</div>
// MatchRow left rail: group on parent, group-hover on rail
<a className="group relative …">
  <span className="absolute left-0 top-0 h-full w-[3px] bg-transparent
                   transition-colors duration-150 group-hover:bg-primary" />
```

### Pattern 4: Mobile-first responsive reflow
**What:** Unprefixed = base (phone). Add `sm:`/`md:`/`lg:`/`xl:`/`2xl:` for wider. The Match Row-1 grid example:
```tsx
// Phase 10.3 desktop: flex gap-8 (3 equal columns). Phone-first version:
<div className="flex flex-col gap-6 lg:flex-row lg:gap-8 lg:items-stretch">
  <div className="min-w-0 lg:flex-1">{/* heroes */}</div>
  <div className="min-w-0 lg:flex-1">{/* items */}</div>
  <div className="min-w-0 lg:flex-1">{/* cooldowns */}</div>
</div>
```
`min-w-0` on every flex child is **mandatory** to prevent dense panels forcing horizontal overflow (see Pitfall 2).

### Anti-Patterns to Avoid
- **Leaving any inline hex** — UI-01 forbids it; the verification grep (below) will fail.
- **Shrinking data glyphs to fit** — UI-03 floors are non-negotiable; truncate the `who` label first.
- **`sm:`-prefixing the mobile style** — `sm:text-center` only centers at ≥640px; base style must be unprefixed.
- **Hardcoding the four target widths as custom breakpoints** — Tailwind defaults already cover the reflow; the only design breakpoint is the `1180px` stack threshold (use `xl:` ≈1280 or an arbitrary `max-[1180px]:` / `min-[1180px]:` variant — see Pitfall 3).
- **Editing `tactical-slate.css`** — it's the LOCKED source; copy values INTO `index.css`'s `@theme`, don't import or mutate the sketch file.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Theme token system | Custom CSS var registry + manual class map | Tailwind 4 `@theme` | Generates utilities AND runtime vars from one block; this is the native UI-01 solution |
| Dark-mode handling | `dark:` variant plumbing, theme toggle | Nothing — app is always-dark | No light theme exists; tokens are the single (dark) palette. Do not add `dark:` variants. |
| Responsive breakpoints | Custom media queries in CSS | Tailwind `sm/md/lg/xl/2xl` + `max-*` variants | Defaults already map to the targets; no custom `@media` needed except the one `1180px` threshold |
| Conditional classes | String concatenation / ternary soup | `clsx` (already a dep) | Cleaner responsive/state composition |
| Font self-hosting pipeline | Webpack/Vite font bundling | Google Fonts `<link>` (per SPEC) | SPEC decision; zero build config |
| Container-relative sizing | JS `ResizeObserver` for panel widths | CSS `aspect-ratio` + `max-width` (map), container queries if needed | The map fluid-fix is pure CSS (`width:100%; max-width:420px; aspect-ratio:1`) |

**Key insight:** Tailwind 4 makes the token layer (UI-01) a *configuration* task, not an engineering task. The real effort is the breadth of the mechanical migration across 21 files and getting responsive flex/grid `min-w-0` discipline right — not building any new abstraction.

## Common Pitfalls

### Pitfall 1: HistoryGraphs.test.tsx hard-asserts the retired hex literals
**What goes wrong:** Migrating `HistoryGraphs.tsx` to softened radiant/dire colors makes 6 test assertions fail (`fill === '#4ade80'`, `fill === '#ef4444'`, `style.color === '#4ade80'`). Success criterion 5 ("suite stays green") breaks.
**Why:** The test was written in Phase 10.2 against the old hardcoded palette and asserts exact SVG attribute values.
**How to avoid:** In **Wave 0**, update the test to the new expected values (or to read computed `var(--color-radiant)`). If the component keeps emitting literal hex via `var()` (jsdom may render `fill="var(--color-radiant)"` as the literal string `var(--color-radiant)` since jsdom doesn't resolve CSS vars), assert on the string `'var(--color-radiant)'` instead. **Decide the assertion strategy before migrating the component.**
**Warning signs:** `npm test` shows 6 failures in `HistoryGraphs.test.tsx` only.

### Pitfall 2: Flex/grid children overflow on narrow viewports (UI-02 hard constraint)
**What goes wrong:** Dense panels (ItemsBlock 6×26px slots, ScoreHeader 56px mono, team names) force horizontal scroll on phone because a flex child won't shrink below its content width.
**Why:** Flex items default to `min-width: auto` (won't shrink past content). Long team names + fixed-width glyph rows blow out the row.
**How to avoid:** Add `min-w-0` to every flex child that contains truncatable/dense content; pair with `truncate` (`overflow-hidden text-ellipsis whitespace-nowrap`) on team names. Map: drop fixed `size={420}` → `width:100%; max-width:420px; aspect-ratio:1` (UI-SPEC). Item slots: shrink/truncate the `who` owner column to 48px before touching slots (UI-03).
**Warning signs:** Horizontal scrollbar at 375/768px; right edge of a card clipped.

### Pitfall 3: The 1180px stack threshold doesn't match a default breakpoint
**What goes wrong:** UI-SPEC mandates flipping dense grids to single column at exactly `max-width: 1180px`, but Tailwind defaults are 1024 (`lg`) and 1280 (`xl`) — neither is 1180.
**Why:** 1180 is the sketch's bespoke `.row2` threshold.
**How to avoid:** Use an arbitrary variant: `max-[1180px]:flex-col` / `min-[1180px]:flex-row` (Tailwind 4 supports arbitrary `min-[…]`/`max-[…]` breakpoint variants). OR define a custom `--breakpoint-stack: 1180px` in `@theme` to get a `stack:` variant. Either keeps the exact spec threshold. [CITED: tailwindcss.com/docs/responsive-design — arbitrary `min-[475px]:` variants supported]
**Warning signs:** Grid stacks at the wrong width (1024 or 1280 instead of 1180), causing a cramped 3-col render between 1180–1280.

### Pitfall 4: `@theme` vs `:root` — soft tints / gradients don't need utilities
**What goes wrong:** Putting `--card-bg-grad` or `--color-radiant-soft` in `@theme` generates useless utility classes and can confuse Tailwind's color parsing for non-color values.
**Why:** `@theme` is for tokens that should map to utilities; gradients/soft rgba used only via `var()` shouldn't.
**How to avoid:** Put utility-backed tokens (solid colors, fonts, radii, shadow-card, tracking) in `@theme`; put `var()`-only values (gradients, glows, soft tints) in plain `:root`. Both are runtime vars; only `@theme` ones generate classes. [CITED: tailwindcss.com/docs/theme — "@theme vs :root"]
**Warning signs:** Unexpected `bg-card-bg-grad` class doesn't work as a gradient; build warnings about color tokens.

### Pitfall 5: Imperative JS hover handlers bypass the token layer
**What goes wrong:** Leaving `onMouseEnter={e => e.currentTarget.style.background = '#111111'}` (5 components) means hardcoded hex survives the migration and UI-01's "no inline hex" is violated.
**Why:** These predate the token contract.
**How to avoid:** Replace all five with CSS `hover:`/`group-hover:` utilities per Pattern 3. The MatchRow left rail needs `group` on parent + `group-hover:bg-primary` on the rail.
**Warning signs:** Grep for `style.background`/`style.color` in `onMouse*` still returns hits after migration.

### Pitfall 6: jsdom has no real viewport — responsive behavior is NOT unit-testable
**What goes wrong:** Tests can't verify "no horizontal scroll at 375px" — jsdom doesn't lay out, doesn't apply media queries, doesn't compute element widths.
**Why:** jsdom is a DOM, not a rendering/layout engine.
**How to avoid:** Treat responsive correctness as **manual UAT at each of the 4 widths** (see Validation Architecture). Unit tests stay at the level they already are (logic, presence of elements, structural assertions). Do NOT write brittle media-query unit tests.
**Warning signs:** Temptation to assert `window.innerWidth` / `getBoundingClientRect` (returns 0 in jsdom).

   - Recommendation: define `--breakpoint-stack: 1180px` in `@theme` → cleaner `stack:`/`max-stack:` variants reused across Home + Match. Discretion, but a named breakpoint reads better across many files.

3. **Off-grid arbitrary pixel utilities (`text-[11px]`, `w-[3px]`) — keep as arbitrary, or tokenize?**
