## Critical Context Finding (affects every pillar below)

**The shipped codebase no longer runs the theme this UI-SPEC describes.** `client/src/index.css` carries a comment stating the token layer was **replaced wholesale** by a later "Neon Bento" redesign:

```css
/* Neon Bento token layer — canonical source: .planning/sketches/redesign-2026/neon-bento/_theme.css.
   Modular OLED dashboard: Plus Jakarta Sans, deep-black surfaces, violet + gold accents.
   Token NAMES preserved from the prior theme so existing component utilities re-skin automatically. */
```

Concretely, every color/font token this UI-SPEC locks has been overwritten:

| Token | UI-SPEC (Tactical Slate) | Actual (`index.css`) |
|---|---|---|
| `--color-bg` | `#14151a` | `#08080F` |
| `--color-primary` | `#d4a24a` (gold) | `#8B5CF6` (violet) |
| `--color-accent` | `#5b9bd5` (steel blue) | `#FBBF24` (gold) |
| `--color-radiant` | `#6bcf8a` (softened) | `#4ADE80` (original, un-softened) |
| `--color-dire` | `#e06a72` (softened) | `#F87171` (original, un-softened) |
| Font | Inter | Plus Jakarta Sans |
| Home IA | league-accordion match-row list | calendar + MatchRail + MatchBentoGrid |

10.4-08-SUMMARY.md's sign-off ("automated sweep clean… only allowlisted `HistoryGraphs.tsx` `#6bcf8a`/`#e06a72` remain") describes a state that **no longer exists in the working tree** — the file today hardcodes `#4ade80`/`#f87171`, the pre-softening originals (`HistoryGraphs.tsx:34-35`), and the token layer itself reverted to the same un-softened values. This is either a later phase that silently re-themed the app without updating/superseding this UI-SPEC, or a regression. Either way, **this UI-SPEC is not the operative contract for the current UI** and cannot be used as a literal pass/fail baseline for color/typography — I've scored those pillars against the abstract 6-pillar standard applied to what's actually shipped, and flagged spec-drift separately as a process finding rather than double-penalizing color choices that are internally consistent under the new (undocumented) theme.

This does **not** excuse the accessibility and consistency defects below, which are theme-independent.

## Top 3 Priority Fixes

1. **IntelTooltip is unreachable by keyboard or touch on `DraftPortrait.tsx` and `PlayerRow.tsx`** — counter-pick data (a core analytical feature) is invisible to any non-mouse user; only `StandingsTable.tsx` correctly pairs `onMouseEnter`/`onMouseLeave` with `onFocus`/`onBlur`. Fix: add `onFocus`/`onBlur` (and `tabIndex={0}` on the trigger) mirroring `StandingsTable.tsx:219-224`, and add a tap-to-toggle path for touch.

2. **No `:focus-visible` styling exists anywhere in the app** (`grep -rn "focus-visible" index.css components pages` returns zero hits). Every interactive element — match rows, nav buttons, league headers — is keyboard-invisible: a sighted keyboard user cannot tell what's focused. Fix: add a global `:focus-visible` rule (e.g. `outline: 2px solid var(--color-primary); outline-offset: 2px`) in `index.css`, scoped to interactive elements.

3. **Typography scale has drifted to 7 sizes / 5 weights against a contract of 4/2.** `font-bold` (700) appears 31 times, `font-extrabold` (800) 2 times, alongside `font-normal`/`font-medium`/`font-semibold` — this is an uncontrolled prose hierarchy, not a numeric-display exemption (the numeric exemption in the spec is for mono glyphs specifically, and much of this bold usage is on Tailwind text, not `font-mono`). Fix: audit `font-bold`/`font-extrabold` usage; collapse non-numeric instances to `font-semibold`, reserve `font-bold`/`extrabold` strictly for `font-mono` numeric glyphs (kill score, K/D/A, net worth) per the contract's carve-out.

## Detailed Findings

### Pillar 1: Copywriting (3/4)
- No generic `Submit`/`Cancel`/`OK`/`Click here` labels found in shipped components (`grep` across `components/`, `pages/` clean; only a test-file mock `<div>OK</div>`).
- `ErrorBanner.tsx:15-16` implements the exact UI-SPEC copy verbatim: *"Couldn't load live matches."* / *"We'll keep retrying automatically. Check your connection if this persists."* — good, direct compliance.
- However, the UI-SPEC's Home-page copy contract ("Live matches" section label, "No live matches right now" empty state, league-accordion IA) describes a page that no longer exists — `HomePage.tsx` is now a calendar + `MatchRail` + `MatchBentoGrid` architecture (`pages/HomePage.tsx:1-40`). Cannot verify those specific strings are honored because the IA they were written for was replaced. Docked one point for this unverifiable/stale contract state rather than an actual copy defect.

### Pillar 2: Visuals (3/4)
- Each page has an identifiable focal point (ScoreHeader on Match, calendar+rail on Home) — hierarchy through size/weight is present.
- `AppNav.tsx:110` correctly uses `aria-label="Main"` on the nav; nav buttons have visible text, not icon-only — good.
- Counter/intel affordance (`IntelTooltip`) is the app's richest secondary-visual feature but is entirely hover-gated on 2 of 3 trigger components (see Experience Design pillar) — a visual-hierarchy element that's invisible to a whole class of users is a real visuals defect, not just an interaction one.

### Pillar 3: Color (2/4)
- Token layer is internally consistent (Neon Bento) but directly contradicts the locked UI-SPEC values (see Critical Context Finding above) — not scored as a direct violation since the spec appears superseded, but the underlying "softened team colors" requirement was never carried forward into whichever theme is now canonical: `index.css:37-38` and `HistoryGraphs.tsx:34-35` still use the original saturated `#4ADE80`/`#F87171` that the (stale) 10.4-UI-SPEC explicitly called out as too harsh and specced softened replacements for. Whatever theme governs now, this specific defect (harsh saturated team-color reds/greens) was flagged by both this spec and a prior engineering audit and is still unfixed.
- Two literal color constants (`RADIANT_GREEN`, `DIRE_RED` in `HistoryGraphs.tsx:34-35`) exist purely because `jsdom` can't resolve `var()` in SVG — this is a maintained, intentional exception (per code comment), not an oversight, and is low risk since it's a single duplication point kept in sync by test coverage. Acceptable engineering tradeoff, but still two sources of truth for the same color.
- No other hardcoded hex found outside `HistoryGraphs.tsx`/tests — the token migration itself (UI-01's core ask) has held up well elsewhere; components consistently reference `var(--color-*)`.

### Pillar 4: Typography (1/4)
- Distinct Tailwind font-size classes in use: `text-xs`, `text-sm`, `text-base`, `text-lg`, `text-xl`, `text-2xl`, `text-4xl` — **7 sizes** against a contract of exactly 4 (this count excludes the many arbitrary `text-[Npx]` values used for mono numerics, which are a separate, allowed system).
- Distinct font-weight classes: `font-normal`, `font-medium`, `font-semibold`, `font-bold` (31 occurrences), `font-extrabold` (2 occurrences) — **5 weights** against a contract of exactly 2 for prose. `font-bold`/`font-extrabold` are contractually reserved for `font-mono` numeric display glyphs only; a spot check (`ScoreHeader.tsx:131,185`) shows `font-extrabold` correctly paired with `font-mono` there, but the 31 `font-bold` occurrences were not individually verified to all be mono-numeric — given the volume, it's implausible all 31 are kill-score/KDA/net-worth glyphs.
- This is a real, uncontrolled prose hierarchy regardless of which theme is canonical — the 6-pillar abstract standard (>4 sizes / >2 weights flag) is independently violated.

### Pillar 5: Spacing (2/4)
- 39 files contain arbitrary bracketed pixel spacing (`grep -rln "\[[0-9]+px\]"`), e.g. `[11px]`, `[10px]`, `[9px]`, `[5px]`, `[18px]`, `[13px]` — values with no relationship to the 4/8/16/24/32/48/64 scale. Some of these are legitimately exempt (fixed data-glyph dimensions the spec explicitly carves out — item slots, map blips), but the sheer breadth (39 files) suggests arbitrary values have become the default escape hatch rather than the exception.
- No `44px` (or `min-h-11`) touch-target minimum found anywhere in the component tree (`grep -rn "44px\|min-h-11\|h-11"` across `components/*.tsx` returns nothing but two unrelated `44px` used as a font-size breakpoint value in `ScoreHeader.tsx`, not a tap-height). The UI-SPEC's non-negotiable phone touch-target contract is unimplemented.

### Pillar 6: Experience Design (2/4)
- **Zero `:focus-visible` rules anywhere** (`index.css`, all `components/*.tsx`, all `pages/*.tsx` — zero matches). No interactive element in the app shows a keyboard-focus indicator. This is a hard accessibility failure that blocks keyboard-only task completion (can't tell what's focused when tabbing through match rows/nav).
- `IntelTooltip` — the app's counter-pick/player-stat surface — is triggered by `onMouseEnter`/`onMouseLeave` only in `DraftPortrait.tsx:76-77` and `PlayerRow.tsx:60-61`; no `onFocus`/`onBlur`, no touch/tap fallback. `StandingsTable.tsx:219-224` shows the correct pattern (`onMouseEnter` + `onFocus`, `onMouseLeave` + `onBlur`) exists elsewhere in the codebase, proving this is an inconsistency, not a technical constraint.
- Loading/error/empty state coverage is broad: 17 of ~60 component/page files reference `isLoading`/`isError`/`isEmpty`/`Skeleton` — reasonable coverage for a data-heavy app, and `ErrorBanner.tsx` centralizes error styling and copy correctly.
- Error-text contrast (`--color-danger` `#EF4444` against its own `--color-dire-soft` background composited over app bg) measures ~4.38:1 — marginal but passes for the semibold header text and is close to (not clearly failing) AA for body text; the previously-reported ~2.7:1 figure could not be reproduced against the current token values and appears to have been addressed, though it remains right at the AA boundary rather than comfortably above it.
