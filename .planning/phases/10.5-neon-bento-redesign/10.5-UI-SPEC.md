# Phase 10.5 — UI Design Contract (Neon Bento)

> **This is a RETROACTIVE contract.** Phase 10.5 shipped 2026-06-14 without GSD artifacts. The
> Neon Bento design system is live in the working tree, and three later bodies of work (Phase 12
> snapshot demo, Phase 13 team avatars, the v2.0 tournament archive) built on top of it without a
> written contract to build against. This document **describes the system that exists** and
> **locks the decisions that were never written down and are therefore drifting**.
>
> It does not propose a new visual direction. Every palette, font, radius and shadow value below
> was read out of `client/src/index.css`. Where this document differs from the shipped code, the
> difference is a **named, measured defect** with a `→` remediation, not a redesign.
>
> **Supersedes `10.4-UI-SPEC.md` entirely.** That document locks the "Tactical Slate" palette
> (`#14151a` bg, gold primary, steel accent, Inter) which was replaced wholesale the same day it
> shipped. Nothing in the codebase has referred to Tactical Slate since 2026-06-14. The 10.4
> spec's *responsive* and *information-density* sections survive and are restated here; its
> color and typeface tables are dead and must not be used as a baseline by any checker or auditor.

### 0.3 Theme scope — dark only, stated explicitly

**This app has exactly one theme and will not gain a light one.** There is no `.dark` class, no
`prefers-color-scheme` branch, no `light-dark()` usage, and none is planned. It is an OLED-first
real-time telemetry dashboard for one viewing context: a dark room with a stream running beside it.

Consequences that are contract, not preference:
- Contrast ratios are computed against `--color-bg` / `--color-surface` / `--color-surface-2` only.
  Every ratio quoted in this document is a real measurement against one of those three.
- Any token whose value only makes sense against a light background is a bug.
- Do not introduce semantic pairs (`--color-fg-on-x`) for a second theme that will not exist.
- Contrast and numeric alignment are **functional requirements**, not polish: the user is reading
  8–12 numeric dimensions in a few seconds while a match is live. A number they misread is worse
  than a number they cannot see.

## 1. Design System

| Property | Value |
|----------|-------|
| Tool | **none** (no shadcn, no `components.json`) |
| Preset | not applicable — Tailwind 4 CSS-first `@theme` layer in `client/src/index.css` |
| Component library | none — hand-built React 19 components in `client/src/components/` |
| Icon library | **none** — inline SVG, CSS shapes, and Unicode glyphs (`★ ⌕ ▶ ‹ › ⚠ ←`) |
| Font (sans) | **Plus Jakarta Sans** — self-hosted, weights 400/500/600/700/800 |
| Font (mono) | **JetBrains Mono** — self-hosted, weights 500/700/800 |
| Font delivery | `client/src/fonts/fonts.css`, generated by `scripts/fetch-fonts.mjs` |
| Styling | Tailwind 4 utilities generated from `@theme` + `var(--…)` for SVG/gradient/shadow contexts |

**Why no shadcn (locked, do not revisit):** every surface in this app is a bespoke data-visualisation
component — a minimap, a Swiss-format flow graph, a playoff bracket, a timeline scrubber, an SVG
lead chart. None of them exist in any registry. Introducing a registry now would add a second
styling vocabulary alongside the `@theme` layer for zero surface coverage. Registry safety gate:
**not applicable** (§8).

**No third-party requests (locked — hard requirement, `DEMO-01`):** webfonts are self-hosted
specifically so the snapshot demo makes zero requests to `fonts.googleapis.com`. The headless
verifier (`DEMO-03`) fails the build on any non-CDN external request. **Never add a `<link>` to a
font CDN, an icon CDN, or an analytics script.** The only permitted external origins are the Valve
art CDNs for hero/item portraits, which are disclosed in the demo banner.

### 2.2 Color roles — 60 / 30 / 10

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#08080F` `--color-bg` | Page field everything floats on |
| Secondary (30%) | `#16152A` / `#1F1D38` | Cards, panels, hover rows, slot fills, popovers |
| Accent (10%) | `#8B5CF6` violet **+** `#FBBF24` gold | See reserved-for lists below |
| Destructive | `#EF4444` `--color-danger` | Error banners and error borders **only** |

**Violet `--color-primary` is reserved for — and ONLY for — "you can act on this":**
- Hover border on `.bento-card`, `MatchCard`, filter chips, calendar cells
- Active / selected state (`--color-primary-soft` fill on active pill, selected day, picked league)
- The focus ring (§6.1)
- Filled primary buttons (via `--color-primary-strong`, see D-6)
- Scrollbar thumb on hover (`.scroll-slim:hover`)
- The featured-tile radial wash on `MatchCard[featured]` and the `PageShell` header glow
- Calendar dot meaning "scheduled"
- Event-log category: **Roshan** (§2.4)

**Gold `--color-accent` is reserved for — and ONLY for — "this is a quantity that matters":**
- Net worth and gold-difference values (`--color-gold`)
- Filled item slot highlight
- Roshan loot drop slots
- `Draft` status tag
- Tier-1 league badge
- Timeline cursor in `HistoryGraphs`
- Event-log category: **Tower / Building** (§2.4)
- "Today" ring in `MatchCalendar`

**Team colors `--color-radiant` / `--color-dire` are reserved for team identity and team-derived
data ONLY.** Kill scores, portrait outline rings, win-prob bar fills, map blips, building tier
dots, chart lines and fills, standings advance/eliminate rails, `Live` status tag (Dire red).
**Never** use a team color for generic chrome, generic emphasis, or a non-team-scoped category.

**Rule (mechanically checkable):** no accent color on generic borders, generic body text, or a
non-semantic background. Team colors are *functional data*, counted separately from the 10%.

### 2.3 Hardcoded-color rule

**Every color in a `.tsx` file must be a `var(--color-*)` reference or a Tailwind utility generated
from `@theme`.** Three exemptions, exhaustively enumerated — anything not on this list is a defect:

1. `HistoryGraphs.tsx` `RADIANT_GREEN` / `DIRE_RED` (documented jsdom constraint, §2.1).
2. `rgba(0,0,0,α)` scrims → **must migrate to the scrim tokens in D-5.**
3. `transparent`, `currentColor`, `none`.

Enforcement grep (should return only `HistoryGraphs.tsx:34-35`):

```bash
grep -rnoE "#[0-9a-fA-F]{3,8}\b" client/src/components client/src/pages --include=*.tsx | grep -v "\.test\."
```

### 2.4 Event-category palette — NEW, closes three collisions

`MatchEventFeed.TYPE_STYLE` and `TimelineScrubber.TICK_STYLE` each map event categories to colors,
independently, and the two maps disagree. Worse, the shipped assignment has **three pairs that are
visually identical at the 3px tick width the scrubber renders**:

| Collision | Detail |
|---|---|
| `kill` (`--color-dire` `#F87171`) vs `barracks` (`--color-danger` `#EF4444`) | Two reds, 3px apart on the same rail, indistinguishable |
| `tower`/`building` (`--color-accent`) vs `aegis` (`--color-gold`) | `--color-accent` and `--color-gold` are **the same hex** |
| `teamfight` vs `roshan` (both `--color-primary`) | Same violet, two meanings |

Additionally, `--color-danger` carrying a *data category* ("Barracks") is a semantic violation of
§2.2 — danger means "something went wrong", not "a building fell".

**Canonical event-category palette (single source of truth — one exported map, consumed by both
`MatchEventFeed` and `TimelineScrubber`):**

| Category | Token | Value | Rationale |
|----------|-------|-------|-----------|
| `kill` / `first_blood` | `--color-dire` | `#F87171` | A kill is team-scoped; red reads as violence |
| `teamfight` | `--color-text-muted` | `#A39FCC` | Neutral — it is a *window*, not a discrete event |
| `tower` / `building` | `--color-accent` | `#FBBF24` | Objective gold |
| `barracks` | `--color-barracks` **(new)** | `#FB923C` | Orange — an escalation of tower gold, distinct from both reds |
| `roshan` | `--color-primary` | `#8B5CF6` | Violet, no longer shared with teamfight |
| `aegis` | `--color-radiant` | `#4ADE80` | The pickup is team-scoped; green distinguishes it from the tower gold |

`--color-barracks: #FB923C` is the **only new palette entry** this contract introduces. It exists
because the shipped palette had no sixth distinguishable hue and was reusing `--color-danger` to
fill the gap. Measured 9.02:1 on `--color-surface`.

| Value | Token | Applies to |
|-------|-------|-----------|
| `0.12em` | `--tracking-label` | Uppercase labels, eyebrows, pills, tags, badges, table heads — the default |

This retires `0.05 / 0.08 / 0.1 / 0.16 / 0.18 / 0.2 / 0.25em` and `tracking-widest` /

> **Owner decision (2026-08-19) — overrides the first draft of this contract.** The draft
> collapsed tracking to a single `0.12em`, retiring `0.3em` as well. The owner kept `0.3em`

> a rule that is only tidier on paper. The split is therefore **by size, not by whim** —
> `0.3em` is permitted at 11px inside Match-page data panels and nowhere else, which keeps
> it mechanically checkable. `PageShell` section titles and card heads still move to
> `0.12em`; that half of the collapse — the same role rendered two different ways — was the
> actual inconsistency and it still gets fixed.

Note: `tracking-[0.12em]` appears 35 times as a literal while the `tracking-label` token that holds
the identical value appears 5 times. **Prefer the token.** Same rule as hex literals.

## 3. Spacing Scale

Tailwind 4 default `--spacing` unit = **4px**. The scale below is the **complete permitted set for
layout rhythm** — gaps, padding and margins that establish the page grid. Two narrowly-scoped
exceptions follow it and are permitted: the 2px sub-grid for intra-component glyph padding, and the
fixed element dimensions, which are element *sizes* rather than layout spacing.

| Step | Value | Usage |
|------|-------|-------|
| `1` | 4px | Item-slot gaps, tier-dot gaps, icon gaps |
| `2` | 8px | Compact element spacing, row gaps |
| `3` | 12px | Default inline gap, panel label margin |
| `4` | 16px | Default block spacing, phone card padding, phone gutter |
| `5` | 20px | Card padding (`MatchCard p-5`), CTA horizontal padding |
| `6` | 24px | Desktop gutter (`md:px-6`), grid gaps between cards |
| `8` | 32px | Major section break |
| `10` | 40px | Page section rhythm (`gap-10` on Home column) |
| `12` | 48px | Large vertical separator |
| `16` | 64px | Page-level rhythm (rare) |

### Sub-grid allowance (2px) — intra-component only

The shipped app uses `0.5` (2px, ×8), `1.5` (6px, ×40) and `2.5` (10px, ×19) heavily, and it is
**correct** for this app: a 24px pill cannot take 4px vertical padding without becoming a 32px pill,
and a match card that is scanned in half a second cannot afford that.

**Permitted:** `0.5` / `1.5` / `2.5` **only** for padding and gaps *inside* a component smaller than
40px — pills, chips, badges, tag glyphs, icon-to-label gaps, table cell padding.
**Forbidden:** for layout rhythm — anything positioning one card relative to another, any section
gap, any page gutter.

**Retired:** `3.5` (14px, 2 uses) → `3` or `4`. `7` (28px, 1 use) → `6` or `8`.

**Arbitrary bracketed spacing is forbidden.** Current offenders, all four of them:
`py-[1px]` (`MatchRail.tsx:136`) → `py-0.5` · `p-[2px]` → `p-0.5` ·
`pt-[18px]` / `mt-[18px]` → `pt-4`/`pt-5`, `mt-4`/`mt-5`.

```bash
# must return nothing
grep -rnoE "\b(p|px|py|pt|pb|pl|pr|m|mx|my|mt|mb|ml|mr|gap|gap-x|gap-y|space-x|space-y)-\[[0-9.]+px\]" \
  client/src/components client/src/pages --include=*.tsx
```

### Fixed element / data-glyph dimensions — NOT spacing

Off-grid by design. These describe *how big a thing is*, not *how far apart things sit*, and are
exempt from the spacing scale. This list is exhaustive; a new fixed dimension must be added here.

| Element | Size | Where |
|---------|------|-------|
| Player portrait | 48×48 | `PlayerRow` |
| Draft portrait | 56×56 (`w-14 h-14`) | `DraftPortrait` |
| Item slot | 25×25 | `ItemsBlock` |
| Counter mini-portrait | 32×32 | `IntelTooltip` |
| Team logo | 24 / 32 (featured) | `MatchCard`, `StandingsTable` |
| Map blip | 9×9 | `DotaMapView` |
| Live dot | 5×5 | `PageShell.LiveCount` |
| Calendar day dot | 4×4 | `MatchCalendar` |
| Standings band rail | inset 3px | `StandingsTable` |
| Scrubber event tick | 3px wide | `TimelineScrubber` |
| Search field height | 36px | `MatchRail` |
| Player row min-height | 52px | `PlayerRow` |
| Scrollbar | 8px | `.scroll-slim` |

### Layout widths (locked)

| Constant | Value | Where |
|----------|-------|-------|
| Shell width | `max-w-[1320px] mx-auto px-4 md:px-6` | `PageShell.SHELL_WIDTH` — **every page, no exceptions** |

## 4. Typography

Plus Jakarta Sans for all prose. JetBrains Mono for **every** numeric, with
`font-variant-numeric: tabular-nums` — this is non-negotiable (§4.3).

### 4.1 Prose scale — exactly 4 sizes, exactly 2 weights

| Role | Token | Size | Weight | Line height | Tracking | Usage |
|------|-------|------|--------|-------------|----------|-------|
| **Label** | `--text-label` | **11px** | **700** | 1.2 | `0.12em`, uppercase | Every micro-label: card heads, section titles, eyebrows, pills, tags, badges, table heads, chips, calendar weekdays, back-links, status captions. Color `--color-text-dim` or `--color-text-muted` |
| **Body** | `--text-body` | **13px** | **500** | 1.45 | normal | Dense panel text: player names, event rows, table cells, standings, schedule rows, tooltips. The workhorse |
| **Body-lg** | `--text-body-lg` | **14px** | **500** | 1.5 | normal | Running prose paragraphs, button labels, form inputs, empty/error state bodies |
| **Heading** | `--text-heading` | **20px** | **700** | 1.2 | normal | The rare non-label card/section head, and empty-state headings |
| **Title** | — | `clamp(1.5rem, 3vw, 2.125rem)` | **700** | 1.0 | `-0.02em` | `PageShell` `h1` **only** — one title scale for the whole app |

**Weight rule: prose uses exactly two weights — 500 and 700.** Nothing else.
Retired: `font-normal` (400, ×5), `font-medium` (deprecated alias, ×1), `font-semibold` (600, ×14),
`font-extrabold` (800, ×2, prose contexts). Plus Jakarta Sans 500→700 has ample separation on OLED;
600 was never doing work that 700 does not do better, and 400 goes muddy on `#08080F`.

**Line-height rule:** any text that can wrap to a second line (`Body-lg`, `Body` in event rows,
tooltips, empty-state bodies) uses its declared ratio. Single-line label and numeric glyphs use
`leading-none` and are exempt.

### 4.2 Collapse map — from the 12 shipped sizes to the 4 above

The three `--text-*` tokens already declared in `index.css` are **currently used by zero
components** — every component hand-writes `text-[Npx]`. That is the drift. These tokens become
real, and their values change to the table above.

| Shipped | Count | → | Notes |
|---------|-------|---|-------|
| `text-[8px]` | 3 | **Label 11px** or `aria-hidden` glyph | `AppNav ▶` and `DraftTimeline` markers are decorative glyphs, not text — size them as glyphs (§3) and mark `aria-hidden` |

### 4.3 Mono numeric ladder — separate system, NOT counted against the prose limits

These are **data glyphs**, not prose. They are declared as a closed set of their own.

| Rung | Size | Weight | Usage |
|------|------|--------|-------|
| Inline | 11px | 500 | Clocks, counts, timestamps, standings W/L, league counts, calendar day numerals |
| Inline-strong | 13px | 500 | K/D/A, net worth, per-row values |
| Card score | 20px | 700 | `MatchCard` kill score |
| Card score, featured | 36px | 700 | `MatchCard[featured]` kill score, `MatchCard` net-worth lead |
| Match score | 40 / 44 / 56px<br>(phone / `md` / `lg`) | 700 | `ScoreHeader` kill score — the Match page's single focal point |

**Mono weights: exactly two — 500 and 700.** `font-extrabold` (800) on `ScoreHeader.tsx:131,185`
drops to 700; at 56px on `#08080F` the two are indistinguishable and 800 is the only place the
weight appears in the app.

**Mandatory-mono rule (mechanically checkable, and the reason this app is readable at all):**
`font-mono` **and** `tabular-nums` are **required together** on every rendered number that can
change between polls or that sits in a column with other numbers. That is: scores, K/D/A, net
worth, gold difference, clocks, respawn/cooldown/Roshan timers, win-probability values, series
scores, W/L records, match counts, minute markers, chart peak labels, calendar numerals.

Numbers *inside a sentence* ("30 seconds", "2 minutes delayed", "3 series") are prose and are
exempt. **A number in a column that is not `tabular-nums` is a defect** — column jitter at 30s
poll intervals is the single most fatiguing thing this UI can do to a reader.

Current gaps: `CooldownsBlock.tsx:191,204`, `ItemsBlock.tsx:133`, `RoshanBlock.tsx:124`,
`MatchPage.tsx:307` use `font-mono` without `tabular-nums`.

**Numeric legibility floor:** no mono numeric below **11px**, ever, at any breakpoint.

## 6. Interaction Contract

Carries forward the validated **"prefer passive over interactive"** principle: this app polls every
30s and the user glances rather than hovers. Static labels beat tooltips; the hover budget is spent
only where hover genuinely adds a dimension (intel tooltips, event details, standings expansion).

### 6.1 Focus indicator — NEW, the headline gap

The app currently has **zero** `:focus-visible` rules. Every interactive element — match cards,
nav pills, calendar days, filter chips, league checkboxes, star toggles, scrubber handles — is
invisible to a keyboard user. `MatchRail.tsx:311` actively removes the browser default with
`focus:outline-none` and replaces it only with a border-color change that is nearly invisible.

**Contract — add to `index.css`:**

```css
@layer base {
  :where(a, button, input, select, textarea, summary, [tabindex]:not([tabindex="-1"])):focus-visible {
    outline: 2px solid var(--color-primary);
    outline-offset: 2px;
    border-radius: var(--radius-sm);
  }
  /* On violet-filled surfaces the violet ring disappears into its own background. */
  .is-primary-filled:focus-visible,
  [aria-pressed="true"]:focus-visible,
  [aria-current="page"]:focus-visible {
    outline-color: var(--color-text);
  }
}
```

Measured: violet ring on `--color-bg` = **4.72:1**, on `--color-surface` = **4.22:1**, on
`--color-surface-2` = **4.02:1** — all clear the 3:1 non-text UI threshold.
`--color-text` ring on a violet fill = **3.83:1** — also clears.

**Rules:**
- `focus:outline-none` / `outline-none` is **forbidden** unless the same element declares an
  equal-or-better `:focus-visible` treatment in the same class list. `MatchRail.tsx:311` must be
  fixed or exempted explicitly.
- Focus order follows visual order. No positive `tabIndex`.
- Anything with an `onClick` is a `<button>` or an `<a>`/`<Link>` — never a bare `<div>`.
  (Currently clean: every `onClick` in the tree is on `button`, `Link`, `input` or a table row that
  correctly carries `tabIndex={0}`.)

### 6.2 Hover / focus / touch parity — closes the tooltip gap

**`StandingsTable.tsx:216-224` is the canonical pattern. Every hover-revealed surface in the app
must match it:**

```tsx
onMouseEnter={() => open(id)}
onMouseLeave={closeSoon}
tabIndex={hasContent ? 0 : undefined}
onFocus={() => open(id)}
onBlur={closeSoon}
```

**Contract:** a hover-only affordance is a defect. Any element that reveals information on
`onMouseEnter` **must** also reveal it on `onFocus`, be reachable via `tabIndex={0}` (or be a
natively focusable element), and dismiss on `onBlur` and on `Escape`.

For **touch**, where neither hover nor focus fires reliably, the trigger must additionally support
tap-to-toggle, or the information must be reachable another way.

Known violations to close:
- `DraftPortrait.tsx:76-77` — `IntelTooltip` (counterpicks, `DRAFT-04`) hover-only
- `PlayerRow.tsx:60-61` — `IntelTooltip` (player hero stats, `PLAYER-01`) hover-only

These are not decoration; they are two of the app's named requirements, currently invisible to
keyboard and touch users.

**Universal rule:** hover is **enhancement only**. Every element's non-hover resting state must be
fully legible on its own. No data is reachable *exclusively* through hover.

### 6.3 Touch targets

**Minimum 44×44 CSS px hit area for every interactive control below the `sm` breakpoint (640px).**

The hit area may be enlarged with padding or a `::before` expander — the *visual* glyph can stay
small. A 24px calendar arrow with a 44px hit box is correct; a 24px calendar arrow with a 24px hit
box is not.

Known violations: `MatchCalendar` month arrows (`w-6 h-6` = 24×24), `MatchCalendar` day cells
(`aspect-square` in a 7-column grid inside a card — ~36px at 375px), `MatchRail` star toggles,
`MatchRail` "Clear" / "Reset" text buttons.

### 6.4 Interaction table

| Interaction | Behavior | Duration |
|-------------|----------|----------|
| Card / tile hover | `border-color` → `--color-primary`. Nothing moves, nothing scales | `--duration-fast` (150ms) |
| Row hover (player, item, cooldown, standings) | `background` → `--color-surface-2` | 150ms |
| Chip / pill active | `--color-primary-soft` fill + `--color-primary` border + `aria-pressed`/`aria-current` | 150ms |

| Charts (`HistoryGraphs`) | **No hover tooltips.** Static peak labels only — validated by sketch 001-C and unchanged | — |
| Live status dot | `animate-pulse` | 1.6s loop |
| Skeletons | `animate-pulse`, laid out in the **same grid shape as the loaded content** so there is no layout jump on arrival | — |
| Scrollable containers | `.scroll-slim` — thumb `--color-border`, `--color-primary` on hover. **Never a default browser scrollbar** on a dark panel | — |
| Tooltip positioning | `createPortal` to `document.body` with `position: fixed`, measured in `useLayoutEffect`, flipping below the anchor within 180px of the viewport top. A horizontal scroller is also a vertical clipper — a tooltip must leave its ancestor's overflow box, not fight it with `z-index` | — |

### 6.5 Motion

**Contract — add to `index.css`:**

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
    scroll-behavior: auto !important;
  }
}
```

`animate-pulse` appears **21 times** (skeletons, live dot, active draft slot) and only
`WinProbBar.tsx:81` currently checks `prefers-reduced-motion`. A dashboard with 21 simultaneously
pulsing elements is genuinely hostile to a vestibular-sensitive reader.

**Motion rules:** no element that carries live data may move, scale, or reflow on hover — the
reader is mid-scan. Color and border transitions only. Nothing animates longer than 200ms except
the two intentional loops (live dot, skeleton shimmer).
