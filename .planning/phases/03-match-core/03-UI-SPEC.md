| Token | Hex | Semantic Role |

Unchanged from Phase 2. Multiples of 4 only.

## Typography

Exactly 4 sizes, exactly 2 weights. No additional sizes or weights permitted.

| Role | Size | Weight | Line Height | Tailwind Class | Usage in Phase 3 |
|------|------|--------|-------------|----------------|------------------|
| Display | clamp(2rem, 6vw, 4.5rem) | 700 (bold) | 1.0 | `font-bold leading-none tracking-tight` | Match title "Team A vs Team B"; kill score numbers (28px is folded into Display — render kill scores at this size or use an explicit `text-[28px] font-bold`) |
| Heading | 20px | 700 (bold) | 1.2 | `text-xl font-bold` | Section headings (Radiant / Dire team label) |
| Body | 14px | 400 (regular) | 1.5 | `text-sm font-normal` | Player name, hero name fallback, gold diff value |
| Label | 12px | 400 (regular) | 1.4 | `text-xs font-normal` | Stat values (K/D/A, NW), countdown, series score, delay disclosure, column headers, respawn timer, GPM/XPM/LH/DN — all chrome-level text uses this size or the 10px sub-label below |

Sub-label note: 10px (`text-[10px]`) is a presentational variant of the Label role — same weight (400), tighter tracking. Use for column headers, hero name line 2, respawn countdown, lane labels in BuildingsSection, back nav, and all ultra-small chrome. It does NOT introduce a fifth type role; it is a size variant within Label.

Typographic decisions for Phase 3 components:

- Kill score numbers (e.g. `24`): Display size (clamp or explicit `text-[28px]`), weight 700, tabular-nums, `font-mono` — large and scannable.
- Match title: Display size (clamp), weight 700, `color: #303030` (ink-3).
- Gold diff (e.g. `+4,200`): 14px (Body), weight 400, tabular-nums. Radiant leading = `color: #4ade80`; Dire leading = `color: #ef4444`.
- Respawn countdown (e.g. `14s`): 10px (Label sub-label), weight 400, centered below portrait.
- Stat column headers (K, D, A, NW, LVL, GPM, XPM, LH, DN): 10px, weight 400, uppercase, `tracking-[0.2em]`, `color: #303030` — barely visible chrome, not competing with data.
- K/D/A values: 12px (Label), weight 400, tabular-nums, `font-mono`.
- Net worth: 12px (Label), weight 400, tabular-nums.
- GPM / XPM / LH / DN: 10px (Label sub-label), weight 400, tabular-nums, `color: #585858`.
- Team name labels in ScoreHeader: 14px (Body), weight 700, uppercase, `tracking-[0.15em]`.

## Color

| Role | Value | Tailwind / Token | Usage |
|------|-------|-----------------|-------|
| Dominant (60%) | `#0a0a0a` | `bg-void` | Page background, match page wrapper |
| Secondary (30%) | `#0f0f0f` – `#141414` | `bg-surface` / `bg-panel` | Score header surface, player rows hover, section dividers |
| Accent (10%) | `#b03030` | `text-ember` / `bg-ember` | Reserved elements only (see below) |
| Radiant | `#4ade80` | `text-radiant` | Radiant kill score, Radiant gold when leading, Radiant team label |
| Dire | `#ef4444` | `text-dire` | Dire kill score, Dire gold when leading, Dire team label |
| Muted text | `#585858` | `text-ink-2` | GPM, XPM, LH, DN values; secondary player stats |
| Destructive | `#ef4444` | `text-dire` | No destructive actions in Phase 3 — reused for Dire semantic only |

Accent (`#b03030` ember) reserved for:
- Back nav hover state (matches MatchPlaceholder pattern)
- Ambient top glow (`radial-gradient` behind match heading, opacity ~0.03)
- StatusTag "Live" dot glow (established in Phase 2 StatusTag)
- Nothing else — kill scores, gold diff, and team labels use radiant/dire, not ember

Gold diff color rule:
- Radiant net worth > Dire: display as `+X,XXX` in `color: #4ade80` (radiant token)
- Dire net worth > Radiant: display as `-X,XXX` in `color: #ef4444` (dire token)
- Equal: display as `±0` in `color: #303030` (ink-3, neutral chrome)

Dead hero portrait overlay:
- `opacity: 0.3` on the `<img>` element (no CSS filter, no red tint per D-06)
- Respawn countdown rendered in `color: #585858` (ink-2) below the portrait

Building state:
- Standing (tower/rax present): full opacity (`opacity: 1`), dot color matches team (radiant/dire)
- Destroyed: `opacity: 0.2`, dot color `#303030` (ink-3)

## Component Inventory

All components hand-built with Tailwind utilities + inline `style` objects. No external library.

### Carried From Phase 2 (unchanged)

- `<StatusTag>` — reused as-is. "Game over" state added: `{ dot: '#252525', text: '#383838' }` using existing "Unknown" style map entry (no new variant needed — "Post-game" maps to this slot, or add a `'Game over'` key).
- `<SkeletonRow>` — pattern reused for `<SkeletonPlayerRow>` (see below).
- `<ErrorBanner>` — reused for match-not-found redirect (no render needed; redirect handled in hook).

### New: `<MatchPage>` (replaces `MatchPlaceholder`)

Root page component for `/match/:matchId`. Structure:

```
<div bg-void min-h-screen px-8 relative>
  ├── Ambient top glow (radial-gradient, ember at ~3% opacity)
  ├── Back nav ("← Back to matches")
  ├── Match title h1 (Team A vs Team B — display font, ink-3 color, clamp sizing)
  ├── <ScoreHeader> (score, gold diff, series score, delay disclosure)
  ├── <HeroPlayerGrid> (Radiant side then Dire side, 5 rows each)
  ├── <BuildingsSection> (lane schematic — hidden when unavailable)
  └── (Phase 4 placeholder: Draft section — not rendered in Phase 3)
</div>
```

Section vertical separation: `mt-12` (48px) between ScoreHeader, HeroPlayerGrid, BuildingsSection.

### New: `<ScoreHeader>`

Displays the top-level match state. Single horizontal row, centered or two-column layout.

Layout:
```
[RADIANT TEAM NAME]   [Kills: 24]   [+4,200]   [Kills: 18]   [DIRE TEAM NAME]
                              ↑ gold diff centered
```

Exact layout spec:
- Container: `flex items-center justify-between px-0 py-6` — no extra horizontal padding (inherits page `px-8`)
- Left block: Radiant team name (`text-radiant`, `text-sm font-bold uppercase tracking-[0.15em]`) + kill score below or beside (Display size, `font-bold tabular-nums font-mono color: #d8d8d8`)
- Center block: Gold diff number (`text-sm tabular-nums font-mono`) + delay disclosure below (`text-[10px] tracking-[0.1em] color: #303030`)
- Right block: Mirror of left block, dire side. Kill score in `color: #d8d8d8`, team name in `color: #ef4444`
- Series score: `text-[10px] tracking-[0.1em] tabular-nums color: #303030` — placed beneath team name on each side
- Delay disclosure: `~{delay}s delay` (use `stream_delay_s` from API; fall back to `~120s delay`). Shown below gold diff. `text-[10px] tracking-[0.15em] uppercase color: #303030`
- Divider below ScoreHeader: `border-b border-lift` (1px, `#1a1a1a`)

### New: `<HeroPlayerGrid>`

Two visual blocks (Radiant / Dire), each containing 5 `<PlayerRow>` components. Radiant renders first (top), Dire below with `mt-8` separation.

Section label above each group: `text-[10px] uppercase tracking-[0.3em] font-bold` — Radiant in `color: #4ade80`, Dire in `color: #ef4444`. Label has `mb-2` spacing (8px).

### New: `<PlayerRow>`

One row per player. Column order (left to right) — locked by this spec:

```
[Portrait] [Player name / hero name] [LVL] [K / D / A] [NW] [GPM] [XPM] [LH / DN]
```

Detailed column spec:

| Column | Width | Typography | Notes |
|--------|-------|-----------|-------|
| Portrait | 48px | — | `<img>` 48×48, `object-cover rounded-sm`; overlay `opacity: 0.3` when dead |
| Name | flex-1 | Body 14px / 400 | Player name line 1; hero name line 2 in `text-[10px] font-normal color: #303030` (if available) |
| LVL | 28px | 12px / 400, tabular | Level number; `color: #585858` |
| K / D / A | 64px | 12px / 400, mono, tabular | Format: `kills / deaths / assists`; deaths in `color: #ef4444`, kills+assists in `color: #d8d8d8` |
| NW | 56px | 12px / 400, tabular | Format: `4,200` (comma-formatted); `color: #d8d8d8` |
| GPM | 40px | 10px / 400, tabular | `color: #585858`; hidden if field absent |
| XPM | 40px | 10px / 400, tabular | `color: #585858`; hidden if field absent |
| LH / DN | 48px | 10px / 400, tabular | Format: `120 / 4`; `color: #585858`; hidden if fields absent |

Layout: `flex items-center gap-4 px-0 min-h-[52px]` — no extra horizontal padding (inherits page `px-8`).
Row divider: `border-b border-wire` (`#1e1e1e`, 1px) between players, NOT between the two team blocks.
Row hover: `background: #0f0f0f` (surface token). No ember bar on player rows — only match rows on home page had that treatment.

Dead player indication:
- Portrait: `opacity: 0.3` on `<img>` (no filter, no tint)
- Respawn countdown: rendered as `{n}s` in a `<span>` positioned below portrait, `text-[10px] font-normal color: #585858 text-center`
- All stat columns remain visible even when dead (data is still valid)

Hidden profile (`account_id === 4294967295`):
- Show Valve-provided name (from `players[n].name` or team roster) + hero portrait + K/D/A
- GPM, XPM, LH, DN: still render if present in Valve data (`.passthrough()` exposes these)
- No "hidden profile" label in the UI — just render what exists, silently skip what doesn't

Draft state (empty hero slot, `game_state === 2`):
- Portrait: 48×48 gray placeholder box `bg-panel rounded-sm` — no image, no crash
- Name: `—` in `color: #303030`
- All stat columns: `—` in `color: #303030`

Column headers (rendered once above Radiant block, fixed position):
- `text-[10px] font-normal uppercase tracking-[0.2em] color: #303030`
- Matches column widths exactly so headers align with data below
- Content: `LVL`, `K/D/A`, `NW`, `GPM`, `XPM`, `LH/DN`

GPM / XPM / LH / DN optional display rule:
- These four stats render **inline** in the same row (not a secondary row per player)
- If a field is absent (undefined / not in `.passthrough()` output), hide that column for ALL rows in that match (not row-by-row). Detect at grid level before rendering headers.

### New: `<SkeletonPlayerRow>`

Shown during initial match data load (before first fetch completes).

- 10 skeleton rows (5 Radiant + 5 Dire) rendered as placeholder
- Same height as `<PlayerRow>` (52px min)
- Shimmer animation matching `<SkeletonRow>` pattern: `opacity` oscillates 0.4 → 1 → 0.4 at 2.4s ease-in-out
- Three shimmer bars per row: portrait area (48px wide), name area (flex-1), stats cluster (fixed width right)
- `background: linear-gradient(90deg, #181818 0%, #222222 50%, #181818 100%)`
- Height: 1px bars (matches existing SkeletonRow minimalist pattern)

### New: `<BuildingsSection>`

Lane schematic for tower and barracks state. Hidden entirely when `buildingDecoder()` returns `unavailable: true` (D-10).

Layout: two-column grid (Radiant | Dire), three rows (Top / Mid / Bot).

```
          RADIANT         DIRE
Top       T1  T2  T3 R M  |  M R T3 T2  T1
Mid       T1  T2  T3 R M  |  M R T3 T2  T1
Bot       T1  T2  T3 R M  |  M R T3 T2  T1
```

- Section label: `text-[10px] font-normal uppercase tracking-[0.3em] color: #303030 mb-4`
- Lane labels (Top / Mid / Bot): `text-[10px] font-normal uppercase tracking-[0.2em] color: #303030`
- Each building: a circle dot, 8px diameter (`w-2 h-2 rounded-full`)
  - Standing + Radiant: `background: #4ade80`, `opacity: 1`
  - Standing + Dire: `background: #ef4444`, `opacity: 1`
  - Destroyed (either side): `background: #303030`, `opacity: 0.25`
- Gap between building dots in a lane: `gap-1` (4px)
- Gap between Radiant / Dire column halves: `gap-6` (24px) with a center rule `border-l border-wire` (1px)
- Container: `px-0 py-4` — no extra horizontal padding

## Loading States

**Chosen approach: skeleton rows matching the existing shimmer pattern.**

Rationale: The MatchPlaceholder already uses the void/surface aesthetic with no spinner. A full-page spinner would break the spatial continuity. Skeleton rows maintain layout structure so the page does not reflow when data arrives.

| State | What renders |
|-------|-------------|
| Initial load (match data loading) | `<SkeletonPlayerRow>` × 10 in place of `<HeroPlayerGrid>`; `<ScoreHeader>` shows `—` dashes in kill score / gold diff placeholders (inline skeleton, no separate component) |
| Match not in cache (direct URL nav) | Show SkeletonPlayerRow × 10; trigger `useLiveGames` refetch; redirect to `/` if match still absent after fetch |
| 30s background refetch | Silent — no skeleton, no spinner, existing data stays visible |
| Post-game (`game_state === 6`) | Freeze last known data; polling stops; StatusTag shows "Post-game" |
| Draft state (`game_state === 2`) | Empty portrait slots; zero stats with `—` placeholders; BuildingsSection hidden |

No full-page spinner. No loading overlay. No blinking.

## Interaction Contract

### Navigation
- Back nav: `<Link to="/">` — `text-[10px] font-normal uppercase tracking-[0.25em] color: #303030`, transitions to `color: #b03030` on hover (160ms ease). "← Back to matches" copy (Phase 2 established).
- No forward navigation from match page in Phase 3 (team/player links are Phase 5+).

### Polling
- `refetchInterval: 30_000` (plain number) — Phase 3 spec. Dynamic interval is Phase 4 work.
- Polling stops when `game_state === 6`: set `refetchInterval` to `false` or `0` in the query options.
- Data is not cleared on re-poll — stale data stays visible between fetches (no skeleton re-render on background refetch).

### Post-game freeze
- When `game_state === 6`: last fetched data displayed, `refetchInterval` → `false`.
- StatusTag switches to "Post-game" label using existing status style.

### Dead hero interaction
- Portrait dims to opacity 0.3 automatically when `respawn_timer > 0`.
- Countdown counts down client-side only if real-time timer is implemented; otherwise displays the last-fetched value (static number, re-synced every 30s with refetch).
- Phase 3 scope: display last-fetched `respawn_timer` value as a static number. No client-side countdown (that's an enhancement for a later phase).

### BuildingsSection visibility
- Rendered only when `buildingDecoder()` returns `unavailable: false`.
- No animation on appear/disappear — section is either present or absent.

## Accessibility Notes

Desktop-first per REQUIREMENTS.md. Minimum touch-target compliance carried forward as practice.

- Portrait images: `alt="{heroName}"` attribute from `heroMapper()`, or `alt=""` for empty slots.
- Dead overlay: conveyed by countdown text below portrait — not color alone.
- Score: team name labels adjacent to kill scores — not color alone (both color + position encode Radiant vs Dire).
- BuildingsSection dots: not keyboard-interactive — display only, no role needed.
- Column headers: plain `<span>` elements, not `<th>` (not a `<table>` layout — use flex). Acceptable for a data display widget without interactive rows.
- Back nav: `<Link>` is keyboard-navigable via browser default.
