# Phase 10.2: HistoryGraphs Polish + Right-Column Equalize + XP Fix — Research

**Researched:** 2026-05-14
**Domain:** UAT-feedback fix-up (server schema bug + client chart redesign + flex layout)
**Confidence:** HIGH (root cause of XP bug confirmed in code; sketch winner already wrapped; layout mechanics inspected)

## Summary

This is a three-concern UAT fix phase, but the three concerns are largely independent and have different risk profiles. The XP bug has a **single, confirmed root cause**: the server live route already remaps Valve's actual field names (`xp_per_min` → `xpm`, `gold_per_min` → `gpm`) when projecting scoreboard stats onto top-level `players[]` (`server/src/routes/live.ts:88-89`), but the history sampler reads `xpm` directly from the **raw** `g.scoreboard?.radiant?.players[]`, where the field is still named `xp_per_min`. Result: every sample's `xpm` is `undefined`, contributing 0 to the per-team XP sum, producing the observed `0.0k` flat chart. The unit tests in `server/src/services/historySampler.test.ts` use `xpm` directly as the input field and so pass — they encode the bug as expected behavior. Net_worth (used for gold) is the same field name in both the Valve scoreboard payload and the top-level player schema, which is why the gold chart works.

The chart redesign is a near-total rewrite of `client/src/components/HistoryGraphs.tsx` against the canonical sketch in `.claude/skills/sketch-findings-dota-stats/references/charts-data-viz.md` (winner: variant C). Hover infrastructure (~80 lines of state, ref, mouseMove handler, tooltip JSX) gets deleted; static peak detection + edge-anchor clamping + headline value get added. The 12-test test file is heavily coupled to the current implementation (4 tests assert mouseMove/tooltip behavior, 1 asserts a specific midline Y value 74 from the current 160px H) and must be rewritten alongside the component.

The right-column equalize is the smallest concern but has a layout-correctness subtlety: `DotaMapView` is a fixed-pixel 320×320 SVG (`const S = 320`) and cannot stretch via `flex-1` without breaking hero position calculations (positions are computed in SVG units, not container percentages). `RoshanBlock` and `CooldownsBlock` already have `flex flex-col flex-1` on their root, but the parent `<div className="flex flex-col gap-8" style={{ width: 320 }}>` has no fixed height, so `flex-1` is currently a no-op on a column flex with intrinsic-height content. The fix is to constrain the right column to the height of `HeroPlayerGrid` (the left sibling) via the existing `items-stretch` on the outer flex row, then make the right column itself `h-full` so its children can resolve `flex-1`.

**Primary recommendation:** Fix the XP bug by mapping `xp_per_min` (and `gold_per_min` for symmetry) inside `buildSample`, update the test fixture to use the real Valve field name in one test plus keep the existing `xpm`-input tests as a backward-compat layer. Rewrite `HistoryGraphs.tsx` to match the sketch (delete hover, add peaks + headline). Equalize the right column by setting `h-full` on the right column wrapper and removing the fixed `width: 320` in favor of a Tailwind shrink-0 width-class so flex sizing is predictable.

### Anti-Patterns to Avoid

- **Stretching DotaMapView via `flex-1`** — the SVG is a fixed-pixel 320×320 viewBox. Stretching breaks `position_x`/`position_y` -> SVG coord mapping in `mapCoords.ts`. Hero rings would land outside the map image.
- **Pushing the XP fix into the client** — the BFF/Redis stored samples are the cached canonical source; fixing the schema field there means every viewer self-heals from minute 0. A client-side patch would force a special-case re-derive that doesn't have the per-team raw scoreboard data anyway.
- **Deleting the existing `xpm` test cases** — they exercise the fallback path and document an upstream rename risk (Valve has changed this field name at least once already, evidenced by the dual aliases in `live.ts`).
- **Sharing one X-axis across both chart sections** — per `charts-data-viz.md` line 53, gold and XP samples may diverge in cadence. The existing component already keeps them independent — preserve this.

## Common Pitfalls

### Pitfall 1: Test fixture encodes the bug

**What goes wrong:** The current `historySampler.test.ts` passes `xpm: 500` directly into `buildSample` and asserts non-zero XP. After the fix, that test still passes (via the fallback) — but it doesn't test the actual production path.

**Why it happens:** Test fixture was constructed against the historySampler's *typed* interface, not against the real Valve payload.

**How to avoid:** Add a NEW test case that passes `xp_per_min` (no `xpm`) and asserts non-zero XP. Keep existing `xpm`-input tests as a fallback contract.

**Warning signs:** `pnpm test` green after the fix but UAT still shows 0.0k.

### Pitfall 2: HistoryGraphs.test.tsx midline constant breaks under viewBox change

**What goes wrong:** Existing test at line 96 hard-codes `yMid = 74` derived from `H=160, PAD_T=12, PAD_B=24`. The new sketch uses `viewBox 0 0 1000 200` with `padTop=28, padBottom=22, midY=100`. All geometry assertions break.

**Why it happens:** Tests are coupled to internal geometry constants.

**How to avoid:** Rewrite the geometry tests to assert relative position (first point above midline, second below) without binding to specific Y values, OR export the geometry helpers and assert on output rather than DOM.

**Warning signs:** Multiple test failures with "expected N to be less than 74".

### Pitfall 3: DotaMapView aspect-ratio break

**What goes wrong:** A naive `flex-1` on the right column or on DotaMapView itself stretches the SVG, but hero positions are computed in SVG units (`normalizeMapCoords` → 0..320), so stretched SVG → hero rings drift off the map.

**Why it happens:** `width={S}` and `height={S}` in `DotaMapView.tsx:37` are pixel attributes — they're hints, not constraints when the parent forces stretch via CSS.

**How to avoid:** Keep DotaMapView at intrinsic 320×320 via `shrink-0`. Apply `flex-1` only to RoshanBlock and CooldownsBlock (which both already declare it on their root).

**Warning signs:** Hero dots offset from minimap image edges after layout change.

### Pitfall 4: Background sampler writes zero-XP samples between deploy and Redis TTL expiry

**What goes wrong:** UAT immediately after deploy still shows 0.0k flat for the prefix of an in-progress match's series.

**Why it happens:** Pre-fix samples are still at the head of the Redis list; LTRIM caps at 240 but doesn't drop old entries until 240 newer ones land (~2h of 30s ticks).

**How to avoid:** Either (a) test against a match that started after deploy, or (b) for the UAT pass, manually `DEL timeseries:{matchId}` for the specific match being demoed.

**Warning signs:** XP chart shows 0.0k for first N minutes then suddenly takes off.

### Pitfall 5: Cooldown row count exceeds available height

**What goes wrong:** When the right column equalizes to HeroPlayerGrid height (~600-800px), and DotaMapView claims 320px + Roshan claims ~140-200px, CooldownsBlock gets the remainder (~150-300px). With 10 active cooldowns at minHeight: 44px = 440px content, it overflows.

**Why it happens:** CooldownsBlock has no vertical overflow handling; it currently expands to its content's natural height.

**How to avoid:** Add `min-h-0 overflow-y-auto` to the CooldownsBlock root (next to the existing `flex flex-col flex-1`), so it scrolls within its allocated flex-1 space. The `min-h-0` is critical — without it, flex items refuse to shrink below content size.

**Warning signs:** Right column extends below HeroPlayerGrid, breaking visual alignment.

## Code Examples

### XP fix — `buildSample` patch

```ts
// Source: server/src/services/historySampler.ts (proposed change)
export function buildSample(game: {
  scoreboard?: {
    radiant?: { players?: Array<{ net_worth?: number; xp_per_min?: number; xpm?: number }> }
    dire?:    { players?: Array<{ net_worth?: number; xp_per_min?: number; xpm?: number }> }
    duration?: number
  }
  duration?: number
  game_state?: number
}): HistorySample | null {
  if (game.game_state !== 5) return null
  const duration = game.scoreboard?.duration ?? game.duration ?? 0
  if (!duration) return null
  const r = game.scoreboard?.radiant?.players ?? []
  const d = game.scoreboard?.dire?.players ?? []
  if (r.length === 0 || d.length === 0) return null
  const sumNw = (ps: typeof r) =>
    ps.reduce((s, p) => s + (p.net_worth ?? 0), 0)
  // Valve's canonical field name is xp_per_min (verified server/src/routes/live.ts:89).
  // xpm fallback preserves backward-compat with existing test fixtures.
  const teamXp = (ps: typeof r) =>
    ps.reduce((s, p) => s + ((p.xp_per_min ?? p.xpm ?? 0) * duration) / 60, 0)
  return {
    t: Math.floor(duration),
    gold: sumNw(r) - sumNw(d),
    xp: Math.round(teamXp(r) - teamXp(d)),
  }
}
```

### Chart rewrite — section render skeleton

```tsx
// Source: adapted from .planning/sketches/001-history-graphs/001-C-line-soft-fill.html
function ChartSection({ samples, pick, label }: { samples: HistorySample[]; pick: 'gold' | 'xp'; label: string }) {
  const W = 1000, H = 200, padTop = 28, padBottom = 22
  const innerH = H - padTop - padBottom
  const midY = padTop + innerH / 2
  const tMin = samples[0].t, tMax = samples[samples.length - 1].t
  const peak = Math.max(...samples.map(d => Math.abs(d[pick]))) * 1.20 || 1
  const x = (t: number) => ((t - tMin) / Math.max(1, tMax - tMin)) * W
  const y = (v: number) => midY - (v / peak) * (innerH / 2)

  // Peaks
  let rPeak = { v: 0, t: 0 }, dPeak = { v: 0, t: 0 }
  for (const d of samples) {
    if (d[pick] > rPeak.v) rPeak = { v: d[pick], t: d.t }
    if (d[pick] < dPeak.v) dPeak = { v: d[pick], t: d.t }
  }

  // Headline (latest sample)
  const last = samples[samples.length - 1][pick]
  const sign = last >= 0 ? 'Radiant +' : 'Dire +'
  const headline = `${sign}${(Math.abs(last) / 1000).toFixed(1)}k`
  const headlineColor = last >= 0 ? '#4ade80' : '#ef4444'

  // SVG composition order (back-to-front per charts-data-viz.md §SVG composition order):
  //   1. Gridlines  2. Zero line  3. Radiant fill  4. Dire fill
  //   5. Radiant line  6. Dire line  7. Peak dots  8. Peak labels  9. X-axis labels
  return (
    <div className="relative mt-4">
      <span className="absolute top-1.5 left-1.5 text-[11px] uppercase tracking-[0.18em]" style={{ color: '#888' }}>
        {label}
      </span>
      <span className="absolute top-1.5 right-1.5 text-xs tabular-nums" style={{ color: headlineColor }}>
        {headline}
      </span>
      <svg viewBox={`0 0 ${W} ${H}`} preserveAspectRatio="none" style={{ width: '100%', height: 200, display: 'block' }}>
        {/* ... composition layers ... */}
      </svg>
    </div>
  )
}
```
