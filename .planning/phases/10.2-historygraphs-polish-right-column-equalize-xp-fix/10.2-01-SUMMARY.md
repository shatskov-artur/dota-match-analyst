# Phase 10.2 Plan 01: XP Source Fix Summary

One-liner: Closes zero-XP history chart bug by aliasing Valve canonical `xp_per_min` in `buildSample` (mirrors `live.ts:89` pattern), with `Number.isFinite` hardening to prevent NaN/Infinity propagation into Redis time-series samples.

## What Was Built

Two-commit TDD cycle landed the XP source fix:

1. RED — added two failing tests inside the existing `buildSample — pure aggregator (D-07, D-08, D-15..D-18)` describe block in `historySampler.test.ts`:
   - `consumes Valve canonical field name xp_per_min (UAT-XP-01)` — asserts `buildSample` reads real Valve field name; expected diff 4000, was 0 (RED).
   - `treats NaN / Infinity xp_per_min as 0 (defensive hardening)` — locks in `Number.isFinite` guard against malformed inputs; expected diff 6000, was 0 (RED).

2. GREEN — patched `buildSample` body and widened the local `ValveLiveGame` type in `historySamplerJob.ts`.

## Diff Applied

### server/src/services/historySampler.ts

- `buildSample` parameter type widened: each scoreboard player now allows optional `xp_per_min` and `gold_per_min` alongside the existing `xpm` and `net_worth`.
- New `xpmOf(p)` helper: returns first finite value from `[p.xp_per_min, p.xpm]`, else `0`.
- `sumNw` hardened with `Number.isFinite(p.net_worth)` (defensive insurance against malformed `net_worth`).
- Doc comment updated to describe the field-name fallback rationale and reference `server/src/routes/live.ts:89`.
- No change to return shape `{ t, gold, xp }`, no change to gold math, no change to the `Math.round` semantics on XP.

### server/src/services/historySamplerJob.ts

- Pure type widening on the local `ValveLiveGame` type. Both `scoreboard.radiant.players[]` and `scoreboard.dire.players[]` entries gained `xp_per_min?: number` and `gold_per_min?: number`. No body change in `processMatch`, `runOnce`, `startSampler`, or `stopSampler`.
