## Lifecycle таймера

### Where the timer lives

| Option | Description | Selected |
|--------|-------------|----------|
| in-process setInterval на boot (recommended) | New `historySamplerJob.ts` with `startSampler()` / `stopSampler()`, called from `index.ts` before `serve()`. Zero new infrastructure, Railway-friendly. | ✓ |
| Lazy-start от первого запроса | First `/api/live/games` hit arms a module-level setInterval. Doesn't solve the original problem (no viewers ⇒ no history). | |
| Внешний cron через Railway scheduler | Separate cron-job hits an internal endpoint every 30s. Extra infra, auth on endpoint, redundant HTTP layer. | |

**User's choice:** in-process setInterval на boot.

### Dev mode + graceful shutdown

| Option | Description | Selected |
|--------|-------------|----------|
| Включён везде + SIGTERM cleanup (recommended) | Sampler starts in dev/prod; env var owns disablement. SIGTERM/SIGINT clear the interval and await the in-flight tick. | ✓ |
| Только в prod (`NODE_ENV===production`) | Off in dev (`tsx watch` restarts conflict). Only Railway runs the job. | |
| Включён везде, без SIGTERM-handler | Rely on Node default exit; in-flight tick may be SIGKILL'd mid-redis-write — NX-gate + write idempotency would tolerate it. | |

**User's choice:** Включён везде + SIGTERM cleanup.

## Конкурентность тика и overlap

### How to process active matches per tick

| Option | Description | Selected |
|--------|-------------|----------|
| Promise.allSettled по всем матчам (recommended) | Each match its own buildSample → tryWriteSample chain. One bad match doesn't kill the others. Pro tournaments rarely run >10 concurrent live matches. | ✓ |
| Последовательно (`for...of` with await) | Easier to debug, linear log. Total time = N × redis RTT, still <1s in practice. | |

**User's choice:** Promise.allSettled.

### Overlap protection

| Option | Description | Selected |
|--------|-------------|----------|
| Skip-if-running + warn-лог (recommended) | Module-level `isRunning` flag. If next tick fires while previous still running, skip and `logger.warn`. Standard setInterval pattern. | ✓ |
| Без overlap-защиты | Rely entirely on NX-gate (5s) inside tryWriteSample. Two simultaneous ticks coalesce to one write. Simpler but unbounded if redis hangs. | |
| setTimeout-цикл вместо setInterval | After each tick, manually setTimeout(next, 30000). Guarantees 30s between end-of-one and start-of-next; overlap impossible by construction. | |

**User's choice:** Skip-if-running + warn-лог.

## Off-switch / Env-gating

### Switch mechanism

| Option | Description | Selected |
|--------|-------------|----------|
| ENV `HISTORY_SAMPLER_DISABLED=1`, default on (recommended) | Opt-out: enabled in prod and dev without config. Set to `1` to neutralise during incidents. Tests opt out via env or by simply not calling startSampler. | ✓ |
| ENV `HISTORY_SAMPLER_ENABLED=1`, default off | Opt-in: explicit enable on Railway. Safer (nothing runs without config) but easy to forget in prod. | |
| Без ENV-флага | Always on. Disabling requires a code change + deploy. Simpler but no incident kill-switch. | |

**User's choice:** Opt-out flag, default on.

### Behaviour when redis === null and in tests

| Option | Description | Selected |
|--------|-------------|----------|
| Job стартует; tryWriteSample сам short-circuits (recommended) | No new branching — sampler module already returns false/[]/void on null redis. Tick becomes a no-op until Upstash recovers; no restart needed. | ✓ |
| Job не стартует при redis === null | `if (!redis) return` in startSampler. Saves Valve calls when redis is dead, but won't auto-recover after a transient flap. | |

**User's choice:** Job стартует; sampler short-circuits internally.

## Логирование

### Volume

| Option | Description | Selected |
|--------|-------------|----------|
| Минимальный: writes + errors + lifecycle (recommended) | `logger.info` only on `wrote===true` (existing) + start/stop + warn on overlap-skip + error on throws. No per-tick or per-match success log. Free-tier-friendly. | ✓ |
| Per-tick summary + writes + errors | `logger.debug` per tick: `{tick, matches, writes, skipped, durationMs}`. Useful for observability but +120 records/hour in logs. | |
| Verbose: per-match per-tick | Log every match (including NX-gate skips). Excessive for free tier. | |

**User's choice:** Minimal.

### Error handling strategy

| Option | Description | Selected |
|--------|-------------|----------|
| Per-match try/catch + outer try/catch (recommended) | One bad iteration doesn't cancel the others; outer catch handles `getLiveLeagueGames()` throws so the loop survives Valve outages. | ✓ |
| Только outer try/catch | Simpler, but a malformed Valve payload could cancel the whole tick. | |

**User's choice:** Per-match + outer.
