# Phase 10.1: background-history-sampler — Research

**Researched:** 2026-05-09
**Domain:** Node 24 timers + Hono graceful shutdown + vitest fake timers
**Confidence:** HIGH

## Summary

- **Job lifecycle is genuinely trivial:** module-level `let handle: NodeJS.Timeout | null` + `let isRunning = false` + a `runOnce()` async function the timer calls; export `startSampler / stopSampler / runOnce`. All locked in CONTEXT.md — research only fills the runtime/test mechanics.
- **Node 24 `setInterval` does NOT queue missed ticks.** If a tick (which in our case is the `Promise<void>` body, but the timer doesn't await it) takes longer than 30s, the next interval fires on schedule; our `isRunning` flag (D-05) is the only thing preventing concurrent fan-outs. Confirmed: `setInterval` schedules off wall-clock not promise completion. [VERIFIED: Node.js 24 timers docs]
- **`@hono/node-server`'s `serve()` returns a `http.Server` handle** with `.close(cb)` — capture it, install SIGTERM/SIGINT hooks that call `stopSampler()` then `server.close()`. [VERIFIED: @hono/node-server README + source]
- **Test strategy: prefer `runOnce()` for behaviour assertions** (D-04, D-05, D-09), use `vi.useFakeTimers()` for ONE timing test (verifies `setInterval(30_000)` actually fires `runOnce`). Mirrors existing `historySampler.test.ts` style: vi.mock the deps, assert call shape.
- **`tsx watch` dev restarts are safe.** Each restart is a fresh Node process; old process is SIGINT'd and exits cleanly via our shutdown hook. No timer leak across restarts. [VERIFIED: tsx docs]
- **`.unref()` is NOT needed** — Hono's listening server already keeps the event loop alive, and we WANT the interval to keep the process alive while the server is up. Adding `.unref()` would cause the process to exit if Hono's listener ever closed first.

## Node 24 Timer & Shutdown Semantics

| Question | Answer | Source |
|----------|--------|--------|
| Does `setInterval` queue ticks if a previous async body is in-flight? | No. `setInterval` is wall-clock based; it does not await the callback's return value. Async callbacks can overlap unless guarded. Our `isRunning` flag (D-05) is the guard. | [CITED: nodejs.org/api/timers.html#setintervalcallback-delay-args] |
| Does `clearInterval(handle)` cancel an in-flight tick? | No. It only prevents future ticks. An already-running async body continues to completion. `stopSampler()` must `await inFlightPromise` after `clearInterval` for graceful shutdown. | [VERIFIED: Node.js 24 timers behaviour] |
| Do we need `.unref()` on the handle? | No. Hono's HTTP server keeps the loop alive; SIGTERM closes both. `.unref()` would risk premature exit. | [VERIFIED: see CONTEXT.md D-03] |
| SIGTERM behaviour on Railway? | Railway sends SIGTERM, waits ~10s, then SIGKILL. Our `stopSampler()` awaits in-flight tick — RPUSH/LTRIM/EXPIRE are individually atomic so a mid-tick SIGKILL is safe (D-03). | [CITED: railway.app/docs] |

**Implementation shape:**

```ts
let handle: NodeJS.Timeout | null = null
let isRunning = false
let inFlight: Promise<void> | null = null

export async function runOnce(): Promise<void> {
  if (isRunning) { logger.warn({}, 'history sampler tick overlap, skipping'); return }
  isRunning = true
  try { /* getLiveLeagueGames + Promise.allSettled(per-match) */ }
  catch (err) { logger.error({ err: (err as Error).message }, 'history sampler tick failed') }
  finally { isRunning = false }
}

export function startSampler(): void {
  if (process.env.HISTORY_SAMPLER_DISABLED === '1') {
    logger.info({ source: SAMPLER_SOURCE }, 'history sampler disabled via env'); return
  }
  if (handle) return // idempotent
  handle = setInterval(() => { inFlight = runOnce() }, INTERVAL_MS)
  logger.info({ intervalMs: INTERVAL_MS, source: SAMPLER_SOURCE }, 'history sampler started')
}

export async function stopSampler(): Promise<void> {
  if (handle) { clearInterval(handle); handle = null }
  if (inFlight) { try { await inFlight } catch { /* swallowed in runOnce */ } }
  logger.info({ source: SAMPLER_SOURCE }, 'history sampler stopped')
}
```

## Hono Server Lifecycle

`@hono/node-server`'s `serve(options, listener?)` returns a Node `http.Server` (or `http2.Server`). Capture it for shutdown:

```ts
// server/src/index.ts
const server = serve({ fetch: app.fetch, port }, () => {
  console.log(`BFF listening on http://localhost:${port}`)
})

startSampler()

const shutdown = async (signal: 'SIGTERM' | 'SIGINT') => {
  logger.info({ signal }, 'shutdown initiated')
  await stopSampler()
  server.close(() => process.exit(0))
  // Hard timeout — Railway gives ~10s
  setTimeout(() => process.exit(1), 9000).unref()
}

process.on('SIGTERM', () => { void shutdown('SIGTERM') })
process.on('SIGINT', () => { void shutdown('SIGINT') })
```

[VERIFIED: github.com/honojs/node-server README — `serve()` return type is `ServerType` = `http.Server | http2.Server | http2.Http2SecureServer`]

**Note on listener signature:** existing `index.ts` already passes the optional `() => console.log(...)` listener — preserve that, just capture the return value.

## Test Strategy

**Primary approach: direct `runOnce()` invocation.** Matches the existing `historySampler.test.ts` style (no fake timers there — every test calls a function and asserts mock calls).

**Why `runOnce()` over `vi.useFakeTimers()` for behaviour:**
- Faster: no timer plumbing, no `vi.advanceTimersByTimeAsync()` orchestration.
- Clearer: assertions read "given N matches, runOnce produced N tryWriteSample calls" — direct cause/effect.
- Same code path: timer body literally is `() => runOnce()`, so coverage is identical.

**Use `vi.useFakeTimers()` only ONCE** — to prove `startSampler()` actually wires the timer at 30s.

**Minimal example mirroring `historySampler.test.ts` style:**

```ts
import { describe, it, expect, vi, beforeEach } from 'vitest'

vi.mock('./valveApi.js', () => ({ getLiveLeagueGames: vi.fn() }))
vi.mock('./historySampler.js', () => ({
  buildSample: vi.fn(),
  tryWriteSample: vi.fn(),
  deleteHistory: vi.fn(),
}))
vi.mock('../logger.js', () => ({ logger: { info: vi.fn(), warn: vi.fn(), error: vi.fn() } }))

import { runOnce, startSampler, stopSampler } from './historySamplerJob.js'
import { getLiveLeagueGames } from './valveApi.js'
import { buildSample, tryWriteSample } from './historySampler.js'

beforeEach(() => { vi.clearAllMocks() })

it('D-04: allSettled isolates per-match failures', async () => {
  vi.mocked(getLiveLeagueGames).mockResolvedValue({
    result: { games: [
      { match_id: 1, game_state: 5, scoreboard: { radiant: { players: [{}] }, dire: { players: [{}] } } },
      { match_id: 2, game_state: 5, scoreboard: { radiant: { players: [{}] }, dire: { players: [{}] } } },
    ] },
  } as never)
  vi.mocked(buildSample).mockReturnValue({ t: 60, gold: 0, xp: 0 })
  vi.mocked(tryWriteSample)
    .mockRejectedValueOnce(new Error('boom'))
    .mockResolvedValueOnce(true)
  await runOnce()
  expect(tryWriteSample).toHaveBeenCalledTimes(2) // both attempted despite first throwing
})

it('D-07: HISTORY_SAMPLER_DISABLED=1 short-circuits start', () => {
  vi.stubEnv('HISTORY_SAMPLER_DISABLED', '1')
  startSampler()
  expect(getLiveLeagueGames).not.toHaveBeenCalled()
  vi.unstubAllEnvs()
})
```

**SIGTERM test pattern** (without killing the test runner): register the handler the same way `index.ts` does, then `process.emit('SIGTERM')`, then `await stopSampler()` directly and assert `clearInterval`-style behaviour by checking that a subsequent `vi.advanceTimersByTime(60_000)` does not invoke `runOnce` again. Avoid asserting on `process.exit` — wrap or skip that branch in tests.

## Pitfalls

1. **Async `setInterval` callback returning a promise the timer ignores.** The timer fires next tick on schedule even if the previous async body hasn't resolved. Rely on `isRunning` (D-05), not on the timer.
2. **`clearInterval` does not cancel in-flight async work.** `stopSampler()` MUST `await` the in-flight promise; otherwise SIGTERM returns before the current tick's RPUSH completes. Mitigated by capturing `inFlight = runOnce()` in the timer callback.
3. **Forgetting to capture the `serve()` return value** — without the server handle, SIGTERM can't trigger a graceful HTTP close, leaving sockets hanging until Railway SIGKILLs.
4. **Duplicate handler registration in tests.** `process.on('SIGTERM', ...)` accumulates listeners across tests; either install in `beforeAll` + `process.removeAllListeners('SIGTERM')` in `afterAll`, or test `stopSampler()` directly without going through `process.emit`.
5. **`vi.stubEnv` not reset between tests** leaks `HISTORY_SAMPLER_DISABLED=1` into subsequent tests. Always pair with `vi.unstubAllEnvs()` in `afterEach`.
6. **Calling `startSampler()` twice creates two timers.** Make idempotent: `if (handle) return` at the top. Otherwise dev hot-paths or repeated boots double the tick rate.
