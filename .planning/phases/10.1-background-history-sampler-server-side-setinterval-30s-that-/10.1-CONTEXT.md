# Phase 10.1: background-history-sampler — Context

**Gathered:** 2026-05-09
**Status:** Ready for planning

<domain>
## Phase Boundary

Server-side background job that polls `getLiveLeagueGames()` every 30s and runs `tryWriteSample` for every active tournament match — independent of any user request. Reverses Phase 10's D-05 ("no background timer, lazy piggyback") so anyone joining mid-game sees gold/XP history accumulated from minute 0 instead of from their join time. Backend-only; no UI changes. Reuses the existing `historySampler.ts` module (buildSample / tryWriteSample / deleteHistory / readHistory) — the NX-gate inside `tryWriteSample` already deduplicates writes between this background job and the existing `/api/live/games` inline piggyback.

</domain>

<decisions>
## Implementation Decisions

### Job Lifecycle
- **D-01:** **In-process `setInterval` started on server boot.** New module `server/src/services/historySamplerJob.ts` exporting `startSampler()` and `stopSampler()`. `startSampler()` is invoked from `server/src/index.ts` before `serve(...)` so the loop is alive as soon as Node accepts requests. Zero new infrastructure — fits Railway free dyno; no external cron, no scheduler, no internal HTTP endpoint.
- **D-02:** **Sampler runs in dev and prod alike.** No `NODE_ENV` gating in the job itself — environment-specific opt-out is owned by the `HISTORY_SAMPLER_DISABLED` env var (D-07). `tsx watch` restarts during dev are fine: each restart re-creates the timer, no state to lose (timeseries lives in Redis).
- **D-03:** **Graceful shutdown on `SIGTERM` and `SIGINT`.** `stopSampler()` calls `clearInterval(handle)` and awaits the in-flight tick (if any) to finish before resolving — so Railway's deploy SIGTERM doesn't kill the process mid-redis-write. Hooks installed in `index.ts` alongside any existing shutdown logic. Shutdown timeout: best-effort, do not extend beyond what Railway grants (~10s) — if the in-flight tick exceeds that, Node will be SIGKILL'd anyway and the in-progress write is safe (RPUSH/LTRIM/EXPIRE are individually idempotent at this granularity).

### Tick Concurrency & Overlap
- **D-04:** **`Promise.allSettled` over the active matches list.** Each match is its own independent buildSample → tryWriteSample / deleteHistory chain. One bad match (malformed scoreboard, redis hiccup) does not cancel the others. Pro-tournament reality is rarely >10 concurrent live matches, so fan-out is bounded.
- **D-05:** **Skip-if-running guard with warn log.** Module-level `isRunning: boolean`. If the next tick fires while the previous is still in-flight, the new tick logs `logger.warn({...}, 'history sampler tick overlap, skipping')` and returns immediately. Prevents unbounded concurrent ticks if Redis or Valve stalls — NX-gate inside `tryWriteSample` is a write-level safety net, not a tick-level one.
- **D-06:** **Per-match try/catch nested inside an outer tick try/catch.** Inner catch logs and continues to the next match; outer catch handles `getLiveLeagueGames()` throws so the loop survives upstream Valve outages and the next tick gets a clean attempt.

### Off-switch / Env-gating
- **D-07:** **Env flag `HISTORY_SAMPLER_DISABLED=1` (opt-out, default on).** When set, `startSampler()` logs `'history sampler disabled via env'` and returns without scheduling. Read once at startup — toggle requires a redeploy/restart (acceptable: this is an incident kill-switch, not a runtime knob). On Railway: defaults to enabled without any env config; flip to `1` to neutralise the job during incidents or hot-fix rollouts.
- **D-08:** **Tests opt out by either setting `HISTORY_SAMPLER_DISABLED=1` in the test setup OR by simply not calling `startSampler()`.** No test-environment auto-detection in the module — tests own their own setup explicitly.
- **D-09:** **Behaviour when `redis === null` (Upstash misconfigured): job still starts and ticks normally.** Each `tryWriteSample` / `deleteHistory` / `readHistory` already short-circuits internally when `redis` is null (Phase 10 Plan 01 contract). Tick loop becomes a no-op until Redis is back — no special branching required, and a transient Upstash flap auto-recovers without a process restart.

### Logging
- **D-10:** **Minimal log volume.** What is logged:
  - `logger.info({ intervalMs, source: 'historySamplerJob' }, 'history sampler started')` on `startSampler()` success.
  - `logger.info({ source: 'historySamplerJob' }, 'history sampler stopped')` on `stopSampler()`.
  - `logger.info({ source: 'historySamplerJob' }, 'history sampler disabled via env')` when D-07 short-circuits.
  - Existing `logger.info({ matchId, t, gold, xp }, 'history sample written')` from `tryWriteSample` path remains the only per-write log.
  - `logger.warn({ inFlightAgeMs }, 'history sampler tick overlap, skipping')` on D-05 skip.
  - `logger.error({ err }, 'history sampler tick failed')` on outer catch (Valve / unexpected throws).
  - `logger.error({ matchId, err }, 'history sampler match failed')` on per-match inner catch.
  No per-tick start/end log, no per-match success log when nothing was written. NX-gate skips and read-only ticks are silent.

### Upstream Source & Cadence
- **D-11:** Tick interval **30s** (matches the phase's stated cadence and the existing `getLiveLeagueGames()` cache TTL — most ticks hit the cache, only one tick per 30s actually reaches Valve). Defined as `INTERVAL_MS = 30_000` constant inside `historySamplerJob.ts`.
- **D-12:** Tick reads matches via the existing `getLiveLeagueGames()` (the standard cached variant), NOT `getLiveLeagueGamesFast()` — fast variant is for the draft 4s-TTL path, irrelevant here. Reusing the standard helper means the sampler tick automatically benefits from cache coalescing with concurrent `/api/live/games` requests.
- **D-13:** **Active-match filter inside the tick:** iterate `data.result.games ?? []` and process each game whose derived `game_state` is `5` (in-game) or `6` (post-game cleanup). Use the same `derivedGameState` inference as `routes/live.ts` (presence of `scoreboard.radiant.players[]` ⇒ `5` if `game_state` absent). Draft / lobby states (`!== 5 && !== 6`) are skipped — `buildSample` would return null anyway, but skipping early avoids a wasted call.

### Claude's Discretion
- Exact module layout inside `historySamplerJob.ts` (helper extraction for the tick body, naming of the `isRunning` flag, etc.) — keep it small and obvious.
- Whether to expose a tiny test-only `runOnce()` export to drive the tick body without the timer (recommended: yes, makes unit tests trivial; reuses the same code paths the timer fires).
- Whether SIGINT handler is wired in addition to SIGTERM — recommended: both, mirrors typical Node graceful-shutdown patterns; cheap to add.
- Test approach for D-04 / D-05 / D-09: vitest with fake timers (`vi.useFakeTimers()`) or a direct `runOnce()` invocation; planner picks based on what matches Plan 10-01's existing test style.

### Folded Todos
None — no pending todos matched Phase 10.1 scope.

</decisions>

<code_context>
## Existing Code Insights

### Reusable Assets
- `historySampler.ts` (Phase 10 Plan 01) — fully done. Job is a thin orchestrator, not a re-implementer. NX-gate inside `tryWriteSample` is the only thing standing between the background job and the inline `/api/live/games` piggyback creating duplicate writes — both call into the same function and both are dedup'd by the same Redis key (`lastSample:{match_id}`).
- `getLiveLeagueGames()` (cached, 30s) — gives the job a free upstream coalescer. Two consumers (job + `/api/live/games` route handler) ⇒ ~1 Valve call per 30s, not 2.
- `logger` (pino) — structured logs with `source: 'historySamplerJob'` make Railway log filtering trivial.

### Established Patterns
- `routes/live.ts` lines 50-188 = canonical per-match enrichment shape: derive `game_state`, gate on `typeof match_id === 'number'`, inline try/catch wraps redis I/O. Job's per-match body should be a near-copy of lines 155-188 (minus the `history = await readHistory(matchId)` step — the job does not need to read back).
- `services/roshanState.ts` + the `derivedGameState` helper logic — same pattern for inferring `game_state` from `scoreboard.radiant.players[]` presence. Job replicates this inline (small) rather than introducing a new shared util (avoid premature abstraction).
- Fire-and-forget logging: `logger.error` with `(err as Error).message`, never the full err object — same convention as `historySampler.ts`.

### Integration Points
- **`server/src/index.ts`** — call `startSampler()` after env / redis are initialised; install `process.on('SIGTERM', stopSampler)` and `process.on('SIGINT', stopSampler)`.
- **`server/src/services/historySamplerJob.ts`** — new file. Single responsibility: own the timer, the `isRunning` guard, and the tick body that fans `Promise.allSettled` over `data.result.games`.
- **No route changes.** The `/api/live/games` inline block stays exactly as it is — the background job is purely additive coverage.
- **Tests** — `server/src/services/historySamplerJob.test.ts` exercising: D-04 (allSettled isolates failures), D-05 (skip-if-running emits warn), D-07 (env flag short-circuits start), D-09 (redis null no-op), and the SIGTERM/SIGINT cleanup contract. Reuse vitest + the mocking style already in `historySampler.test.ts`.

</code_context>

<specifics>
## Specific Ideas

- Job module file name: `historySamplerJob.ts` (mirrors `historySampler.ts`). Constants `INTERVAL_MS = 30_000`, `SAMPLER_SOURCE = 'historySamplerJob'` for log scoping.
- Env var name: `HISTORY_SAMPLER_DISABLED`. Truthy check: `process.env.HISTORY_SAMPLER_DISABLED === '1'` (avoid the `'true'` / `'TRUE'` ambiguity — keep one canonical truthy value).
- Optional `runOnce(): Promise<void>` export from the job module so tests can drive a tick without `vi.useFakeTimers()`. Same code path as the timer fires; trivial to assert against a redis mock.

</specifics>

<deferred>
## Deferred Ideas

- **Per-match metrics / Prometheus counters** for tick duration, match count, write count — not justified at small private-group scale; revisit only if the small group becomes operationally interesting.
- **Distributed lock across multiple Railway replicas** — irrelevant: free dyno is a single instance. If the project ever scales to multiple workers, NX-gate already prevents duplicate writes; the only cost is N redundant Valve calls (cheap, and Valve does not rate-limit `GetLiveLeagueGames` aggressively).
- **Dynamic interval (e.g. faster sampling near game start, slower near minute 60)** — not in scope; 30s is the contract.
- **Backfill of history for a match that started before the server booted** — not implementable: history is reconstructed from live polling only. Anyone joining a match that was already mid-game when the sampler started will still miss the pre-boot window. Acceptable.
- **Reading a `HISTORY_SAMPLER_INTERVAL_MS` env var to override 30s** — YAGNI. Hard-coded constant.

None spilled over into other phases — discussion stayed within scope.

</deferred>
