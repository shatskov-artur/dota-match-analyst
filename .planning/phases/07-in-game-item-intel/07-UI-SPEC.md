## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Gap between item icon and adjacent icon, rank number internal padding |
| sm | 8px | Gap between rank+portrait group and NW value |
| md | 16px | Gap between NW value and item icon strip |
| lg | 24px | Horizontal padding inside each hero row |
| xl | 32px | Gap between main item strip and backpack group |
| 2xl | 48px | `mt-12` section separator above ItemsBlock (matching HeroPlayerGrid separator) |
| 3xl | 64px | Not used in this phase |

Exceptions:
- Item icon touch targets are not interactive — 32px × 32px display size is sufficient (no 44px rule needed).
- Hero portrait in ItemsBlock row: 48px × 48px — same as PlayerRow portrait. No exception from scale.
- Rank number column: fixed 24px width.
- Neutral slot gap: 8px left-margin separating it from the 6 main slots.
- Backpack group gap: 16px left-margin separating it from neutral slot (or main slots if neutral absent).

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px (text-sm) | 400 | 1.5 |
| Label | 10px (text-[10px]) | 700 (bold, uppercase + tracking) | 1 |
| Heading | 12px (text-[12px]) | 400 | 1 |
| Display | not used in this phase | — | — |

Specific usages in ItemsBlock:
- Section heading "Items" or "Net Worth Ranking": 10px, weight 700, uppercase, `letter-spacing: 0.3em`, color `#555555` — matches HeroPlayerGrid section labels (e.g., "Radiant", "Dire").
- Rank number (#1–#10): 12px, weight 700, tabular-nums, color per team (see Color section).
- NW value (e.g., `12.4k`): 12px, weight 400, tabular-nums, color `#e8e8e8`.
- Column header labels (e.g., "NW", "ITEMS"): 10px, weight 400, uppercase, `letter-spacing: 0.2em`, color `#555555`.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#0a0a0a` | Page background, row background default |
| Secondary (30%) | `#1a1a1a` | Empty item slot fill, section divider border, row hover background (`#0f0f0f`) |

| Accent — Dire (5%) | `#ef4444` | Rank number for Dire heroes |

Additional semantic values (carry-over from established palette):
- Row border-bottom: `#1e1e1e` — same as PlayerRow
- Row hover fill: `#0f0f0f` — same as PlayerRow
- Secondary text / labels: `#555555` and `#888888` — same as PlayerRow
- Primary text: `#e8e8e8`
- Empty slot border: `#2a2a2a`

Accent reserved for:
1. Rank number (#1–#10) — colored `#4ade80` (Radiant) or `#ef4444` (Dire) to convey team membership at a glance.
2. No other uses of accent in this phase.

## Component Inventory

New components introduced in this phase:

### `ItemsBlock`

**File:** `client/src/components/ItemsBlock.tsx`

**Purpose:** Renders all 10 heroes sorted descending by net worth with their item icons.

**Props:**
```ts
interface ItemsBlockProps {
  players: Array<{
    hero_id?: number
    account_id?: number
    team: 'radiant' | 'dire'   // injected at merge step
    net_worth?: number
    item0?: number; item1?: number; item2?: number
    item3?: number; item4?: number; item5?: number
    item_neutral?: number
    item6?: number; item7?: number; item8?: number
  }>
}
```

**Layout — each row (height: 52px min, matching PlayerRow):**

```
[rank#]  [portrait 48×48]  [NW]  [item0][item1][item2][item3][item4][item5]  [gap8][neutral]  [gap16][bp0][bp1][bp2]
 24px     48px              56px  ←————— 6 × 32px + 4px gap each ——————→     1slot             3slots
```

Row is `flex items-center` with `gap-2` (8px) as default between groups. Item strip uses `flex gap-1` (4px) internally.

**Section header (above row list):**
```
"ITEMS"  — 10px, uppercase, tracking-[0.3em], weight 700, color #555555
```

**No column header row** — the layout is self-explanatory from icon sizes. Add a single `"NW"` column label above the NW column if space permits (matches HeroPlayerGrid pattern).

### `ItemSlot`

**File:** inline inside `ItemsBlock.tsx` (no separate file — too small)

**Purpose:** Renders one item slot: item icon OR dark placeholder.

**Sizes:**
- Main slots (item0–item5): 32px × 32px, `border-radius: 4px`
- Neutral slot: 32px × 32px, `border-radius: 4px`, `opacity: 0.75`, faint gold border `1px solid #888866`
- Backpack slots (item6–item8): 32px × 32px, `border-radius: 4px` (opacity set on parent group)

**When item_id === 0 or undefined:**
```css
background: #1a1a1a;
border: 1px solid #2a2a2a;
border-radius: 4px;
```
No icon, no error, no text. Exact pixel square.

**When item_id is known:**
```
<img
  src={`https://cdn.cloudflare.steamstatic.com/apps/dota2/images/dota_react/items/${itemName}.png`}
  alt={itemName}
  width={32}
  height={32}
  style={{ borderRadius: 4, display: 'block' }}
  onError={/* render placeholder div on load failure */}
/>
```

**When item_id is non-zero but not found in items.json:**
Render empty placeholder (same as item_id === 0). Do not show error text. Silent fallback required by success criteria #4.

### `itemMapper` utility

**File:** `client/src/utils/itemMapper.ts`

**Purpose:** `itemId (number) → item name string (key from items.json)`

```ts
// items.json shape (OpenDota /constants/items):
// { [name: string]: { id: number, img: string, dname: string, ... } }
// itemMapper builds a reverse lookup: id → name
function itemMapper(id: number): string | null
```

Returns `null` for unknown IDs (triggers placeholder rendering). Returns the name string (without `item_` prefix if CDN requires bare name — verify during implementation).

## Interaction Contracts

### Polling
- ItemsBlock receives its data from the same hook that powers HeroPlayerGrid (`useMatchDetail` or `useDraftDetail` — whichever already exposes scoreboard player arrays with item fields).
- Polling cadence: 30s in-game, `false` post-game. Inherited from existing match polling. No new polling logic introduced.
- On each new data frame, the row order re-sorts by `net_worth` descending. The rank number reflects the current sort position.

### Hover state (rows)
- Same hover pattern as PlayerRow: `onMouseEnter` sets `background: #0f0f0f`, `onMouseLeave` resets to transparent.
- `transition: background 160ms ease` — matches existing rows.

### Item icon load failure
- `<img onError>` handler replaces the `<img>` with the empty slot placeholder div. No visual error indicator. No console warning exposed to user.

### No item tooltips
- Item hover shows no tooltip. Deferred to v2. Do NOT add tooltip wrappers — they add bundle weight and are explicitly out of scope per CONTEXT.md §deferred.

### Section visibility
- ItemsBlock renders when the scoreboard player array is present (same condition as HeroPlayerGrid).
- When no player data yet (loading), render 10 skeleton rows matching the row height (52px each), same pattern as `SkeletonPlayerRow` in HeroPlayerGrid.
- When game is in draft phase (no scoreboard), ItemsBlock is hidden — no items available yet.

## MatchPage Insertion Point

ItemsBlock is inserted **below HeroPlayerGrid** and **above the Map/Buildings section**:

```tsx
{/* HeroPlayerGrid — existing */}
<div className="mt-12">
  <HeroPlayerGrid ... />
</div>

{/* ItemsBlock — NEW Phase 7 insertion */}
<div className="mt-12">
  <ItemsBlock players={allPlayersWithItems} />
</div>

{/* Map + buildings — existing */}
{!buildings.unavailable && (
  <div className="mt-12 flex gap-8 items-start">
    ...
  </div>
)}
```

`allPlayersWithItems` is built by merging `draft.scoreboard.radiant.players` and `draft.scoreboard.dire.players`, injecting a `team` field, then sorting by `net_worth` descending before passing to ItemsBlock.

## NW Formatting

Use `formatNW(value: number): string`:
- `value >= 1000` → `(value / 1000).toFixed(1) + 'k'` (e.g., `12400 → "12.4k"`)
- `value < 1000` → `value.toString()` (e.g., `850 → "850"`)
- `value === undefined` → `"—"`

This is a new small utility — not a modification of `formatGoldDiff`. Keep them separate.

## Accessibility Notes

- Item `<img>` elements carry `alt={itemName}` for screen reader identification.
- Empty slot placeholder divs carry `aria-label="Empty item slot"`.
- Neutral slot `<img>` carries `alt={itemName + " (neutral)"}`.
- Rank number column carries no `aria-label` — the number is sufficient.
- No interactive elements in this phase — no keyboard trap, no focus management needed.
