## Spacing Scale

Multiples of 4 only. Carried forward from Phase 2/3.

| Token | Value | Usage in Phase 4 |
|-------|-------|------------------|
| xs | 4px (`gap-1`, `p-1`) | Gap between portrait cells inside a row (picks row, bans row) |
| sm | 8px (`gap-2`, `p-2`) | Section label `mb-2` above draft grid; gap between picks row and bans row within a column |
| md | 16px (`gap-4`, `p-4`) | Internal padding inside a team column; horizontal gap between Radiant and Dire columns at narrower widths |
| lg | 24px (`p-6`, `gap-6`) | Horizontal gap between Radiant and Dire columns (default) |
| xl | 32px (`p-8`) | Page horizontal padding — inherited from MatchPage wrapper; DraftSection itself uses `px-0` |
| 2xl | 48px (`mt-12`) | Vertical separation between DraftSection and adjacent sections (ScoreHeader above, HeroPlayerGrid below) — matches existing `mt-12` rhythm on MatchPage |
| 3xl | 64px | Not used in Phase 4 |

Exceptions (all multiples of 4, all justified):

- **Draft portrait size:** 56×56px (`w-14 h-14`). Rationale: slightly larger than the 48px PlayerRow portrait so that hero identity is unambiguous during a live draft scan, while staying inside the CONTEXT.md recommended range of 56–64px. Divisible by 4.
- **Empty placeholder slot size:** 56×56px (same as filled portrait — grid must not reflow as slots populate).
- **Left-edge glow border width:** 2px (matches MatchRow ember hover pattern). NOT a 4-multiple; reused verbatim from Phase 2's established accent bar rule.
- **Ban X overlay stroke width:** 2px (matches glow width for visual consistency).
- **Turn label top margin:** 0 (label sits directly above the column group); label `mb-2` (8px) separates label from portrait grid.

**Accent (`#b03030` ember) reserved-for list (explicit, exhaustive):**

- Back nav hover state (established Phase 2, unchanged)
- Ambient top glow (`radial-gradient` behind match heading, opacity ~0.03 — established Phase 3, unchanged)
- StatusTag "Live" dot glow (established Phase 2, unchanged)

### Ban X Overlay Spec

- Color: `#ef4444` (dire token) at `opacity: 0.75` — legible but not alarming.
- Shape: two crossing strokes inline SVG, `stroke-width: 2`, `stroke-linecap: round`, `viewBox="0 0 24 24"` (`M4 4 L20 20` + `M20 4 L4 20`).
- Sized to match portrait: SVG is `w-full h-full` inside a positioned overlay `div` sized to the portrait (56×56).
- Drop shadow on strokes: `filter: drop-shadow(0 0 2px rgba(0,0,0,0.7))` — keeps the X legible against bright portraits.
- Hero portrait below the X stays at full opacity — hero identity preserved (D-04). Do NOT dim the portrait under the X.

### Left-Edge Glow Spec (Active Column)

Two cues simultaneously per D-06:

1. **Text label** above the draft grid (see Turn Indicator Spec below).
2. **Left-edge ember border + shadow** on the active team's column.

Active state CSS (applied to the outer `DraftColumn` wrapper `div`):
```css
border-left: 2px solid #b03030;
box-shadow: -4px 0 12px rgba(176, 48, 48, 0.25);
background: #111111;   /* very subtle tint; matches MatchRow active hover */
transition: border 160ms ease, box-shadow 160ms ease, background 160ms ease;
```

Inactive state:
```css
border-left: 2px solid transparent;
box-shadow: none;
background: transparent;
```

**Tentative state** (D-08 — first-pick team unknown or count ambiguous):
```css
border-left: 2px dashed #b03030;
box-shadow: -4px 0 12px rgba(176, 48, 48, 0.10);   /* reduced alpha */
background: transparent;                            /* no bg tint in tentative state */
```

The tentative state is visually distinguishable (dashed border + weaker glow) but not alarming. See Turn Indicator Spec for the text-side treatment.

## Component Inventory

All four Phase 4 components are new. No external library. Hand-built with Tailwind utilities + inline `style` objects. Reuses `heroMapper()` (browser-safe, from `client/src/utils/heroMapper.ts`) for hero portraits.

### New: `<DraftSection>`

Top-level draft widget mounted on `MatchPage` between `ScoreHeader` and `HeroPlayerGrid` (D-03). Renders whenever `scoreboard` is present in the match payload (D-09 revised). Consumes the `useDraftDetail(matchId)` hook.

Layout (JSX skeleton):
```tsx
<section className="mt-12">
  {/* Turn indicator label — above the grid, centered between columns */}
  <DraftTurnIndicator
    activeTeam={activeTeam}         // 'radiant' | 'dire' | null
    action={action}                  // 'pick' | 'ban' | null
    tentative={tentative}            // boolean
    gameState={gameState}            // number — hide label entirely if game_state !== 2
  />

  {/* Two-column draft grid */}
  <div className="flex items-start gap-6">
    <DraftColumn
      team="radiant"
      picks={scoreboard.radiant.picks ?? []}
      bans={scoreboard.radiant.bans ?? []}
      isActive={activeTeam === 'radiant' && gameState === 2}
      tentative={tentative && activeTeam === 'radiant'}
    />
    <DraftColumn
      team="dire"
      picks={scoreboard.dire.picks ?? []}
      bans={scoreboard.dire.bans ?? []}
      isActive={activeTeam === 'dire' && gameState === 2}
      tentative={tentative && activeTeam === 'dire'}
    />
  </div>
</section>
```

**Conditional rendering rules (locked by CONTEXT):**

| Condition | What renders |
|-----------|-------------|
| `scoreboard` absent | Component does NOT mount (D-10) — section fully hidden |
| `scoreboard` present, 0 picks + 0 bans | Full empty grid (5 + 7 placeholder slots per team) — reads as progress tracker (D-02) |
| `scoreboard` present, `game_state === 2` | Live draft: filled slots + placeholders + turn indicator visible |
| `scoreboard` present, `game_state === 5` (in-game) | Final draft frozen in place, turn indicator hidden (D-07, D-09) |
| `scoreboard` present, `game_state === 6` (post-game) | Final draft frozen, turn indicator hidden (D-11) |
| `scoreboard` dropped between polls (post-game cleanup) | Section un-mounts gracefully — no error UI (D-11) |

### New: `<DraftColumn>`

One team's draft state. Two rows per column: picks (top, 5 slots) above bans (bottom, 7 slots). Column order: Radiant left, Dire right (D-01). Active column gets the left-edge glow.

```tsx
<div
  className="flex-1 pl-3 py-2"       // pl-3 reserves space for the 2px active border + breathing room
  style={{
    borderLeft: isActive && !tentative ? '2px solid #b03030'
              : isActive && tentative ? '2px dashed #b03030'
              : '2px solid transparent',
    boxShadow: isActive && !tentative ? '-4px 0 12px rgba(176,48,48,0.25)'
             : isActive && tentative  ? '-4px 0 12px rgba(176,48,48,0.10)'
             : 'none',
    background: isActive && !tentative ? '#111111' : 'transparent',
    transition: 'border 160ms ease, box-shadow 160ms ease, background 160ms ease',
  }}
>
  {/* Column group label */}
  <p
    className="text-[10px] uppercase tracking-[0.3em] font-bold mb-2"
    style={{ color: team === 'radiant' ? '#4ade80' : '#ef4444' }}
  >
    {team === 'radiant' ? 'Radiant' : 'Dire'}
  </p>

  {/* Picks row — always 5 slots */}
  <div className="flex items-center gap-1 mb-2">
    {Array.from({ length: 5 }).map((_, i) => (
      <DraftPortrait
        key={`pick-${i}`}
        kind="pick"
        heroId={picks[i]?.hero_id}
      />
    ))}
  </div>

  {/* Bans row — always 7 slots */}
  <div className="flex items-center gap-1">
    {Array.from({ length: 7 }).map((_, i) => (
      <DraftPortrait
        key={`ban-${i}`}
        kind="ban"
        heroId={bans[i]?.hero_id}
      />
    ))}
  </div>
</div>
```

**Row separation:** `mb-2` (8px) between picks row and bans row within a column. No label between the rows — the visual pattern (smaller count = picks, larger count = bans) is unambiguous at these slot counts (5 vs 7), and adding labels would clutter the scan.

### New: `<DraftPortrait>`

A single 56×56 cell. Renders one of three visual states:

1. **Filled pick** — hero portrait only, full opacity.
2. **Filled ban** — hero portrait + red X overlay (SVG, 75% opacity dire red).
3. **Empty slot** — bordered placeholder, 56×56, same border color for both pick and ban empty states (D-05).

```tsx
function DraftPortrait({ kind, heroId }: { kind: 'pick' | 'ban'; heroId?: number }) {
  const heroInfo = heroId !== undefined ? heroMapper(heroId) : null

  if (!heroInfo) {
    // Empty slot — bordered placeholder, same style for picks and bans (D-05)
    return (
      <div
        className="w-14 h-14 shrink-0 rounded-sm"
        style={{
          background: '#141414',           // panel token
          border: '1px solid #1e1e1e',    // wire token
        }}
      />
    )
  }

  return (
    <div className="relative w-14 h-14 shrink-0 rounded-sm overflow-hidden">
      <img
        src={heroInfo.portrait}
        alt={heroInfo.name}
        className="w-14 h-14 object-cover rounded-sm"
      />
      {kind === 'ban' && (
        <svg
          className="absolute inset-0 w-full h-full pointer-events-none"
          viewBox="0 0 24 24"
          aria-hidden="true"
          style={{
            color: '#ef4444',
            opacity: 0.75,
            filter: 'drop-shadow(0 0 2px rgba(0,0,0,0.7))',
          }}
        >
          <path d="M4 4 L20 20" stroke="currentColor" strokeWidth="2" strokeLinecap="round" fill="none" />
          <path d="M20 4 L4 20" stroke="currentColor" strokeWidth="2" strokeLinecap="round" fill="none" />
        </svg>
      )}
    </div>
  )
}
```

**No hover state in Phase 4.** Hero name tooltip is explicitly deferred (CONTEXT §deferred). Cursor remains default; slot is not keyboard-focusable (display-only data).

### New: `<DraftTurnIndicator>`

Text label above the draft grid. Shows `Radiant — picking`, `Dire — banning`, or tentative variants. Hidden when `game_state !== 2` (D-07) OR when inference cannot produce a guess at all.

```tsx
function DraftTurnIndicator({ activeTeam, action, tentative, gameState }: Props) {
  // D-07 — hide entirely outside draft state
  if (gameState !== 2) return null
  // No guess available at all — show a neutral placeholder rather than nothing
  if (!activeTeam || !action) {
    return (
      <p
        className="text-[10px] uppercase tracking-[0.25em] font-bold mb-2 text-center"
        style={{ color: '#303030' }}
      >
        Draft in progress
      </p>
    )
  }

  const color = activeTeam === 'radiant' ? '#4ade80' : '#ef4444'
  const teamName = activeTeam === 'radiant' ? 'Radiant' : 'Dire'
  const label = `${teamName} — ${action === 'pick' ? 'picking' : 'banning'}${tentative ? ' ?' : ''}`

  return (
    <p
      className="text-[10px] uppercase tracking-[0.25em] font-bold mb-2 text-center"
      style={{
        color,
        opacity: tentative ? 0.6 : 1,      // tentative = muted version of the team color
        transition: 'opacity 160ms ease',
      }}
    >
      {label}
    </p>
  )
}
```

Label states (all rendered at the same text size / spacing — only color + trailing `?` + opacity change):

| State | Example copy | Color | Opacity |
|-------|-------------|-------|---------|
| Active confident — Radiant picks | `Radiant — picking` | `#4ade80` | 1.0 |
| Active confident — Radiant bans | `Radiant — banning` | `#4ade80` | 1.0 |
| Active confident — Dire picks | `Dire — picking` | `#ef4444` | 1.0 |
| Active confident — Dire bans | `Dire — banning` | `#ef4444` | 1.0 |
| Active tentative (D-08) | `Radiant — banning ?` | team color | 0.6 |
| No guess available (inference returned null) | `Draft in progress` | `#303030` (ink-3) | 1.0 |
| Outside draft state | (component returns `null` — label hidden entirely) | — | — |

Label placement: **centered over the two-column grid**, with `mb-2` separating it from the portrait grid below. This keeps one label for both columns rather than duplicating over each — the glow on the active column disambiguates which team the label refers to.

## Loading States

Carried forward pattern from Phase 3: inline skeleton / placeholder, never a spinner, never a blocking overlay.

| State | What renders |
|-------|-------------|
| `scoreboard` absent (pre-draft lobby, or before first `useDraftDetail` fetch) | DraftSection does not mount. MatchPage layout collapses to ScoreHeader → HeroPlayerGrid → Buildings — no reserved empty space. |
| `useDraftDetail` initial fetch in flight, `scoreboard` not yet seen | DraftSection does not mount (same as above). The first successful fetch mounts the section — no reflow skeleton. |
| `scoreboard` present, 0 picks + 0 bans | Full placeholder grid (5 pick + 7 ban slots per team) — **this IS the loading state** for a draft that just started. Reads as a progress tracker; users see the grid fill in. |
| Polling fetch in flight (background) | Silent — no skeleton, no flash. Existing slots stay rendered until the next payload arrives. |
| `useDraftDetail` error (network / 404 / 5xx) | DraftSection does NOT render. The rest of MatchPage continues to work. **Rationale:** draft is one section among many; a failure here must not take down the match screen. This matches the Phase 7 error-boundary philosophy (not implemented until Phase 7, but designed-for now). |
| `game_state` transitions 2 → 5 (draft ends) | Picks/bans freeze; turn indicator un-renders; column glows fade out (160ms transition). No skeleton. |
| `game_state === 6` (post-game) | If `scoreboard` still in payload: draft stays visible, turn indicator hidden. If `scoreboard` dropped: section un-mounts. |

**No spinner. No overlay. No loading text.** The placeholder grid is the loading affordance.

## Interaction Contract

### Polling Cadence (D-12 / D-13 / D-14 / D-15 / D-16)

- New hook `useDraftDetail(matchId)` polls `GET /api/live/draft/:matchId`.
- `refetchInterval` is a dynamic callback: `(q) => q.state.data?.game_state === 2 ? 5_000 : false`.
- Outside of `game_state === 2`, the hook fetches once and **stops polling** (the scoreboard is frozen after the draft ends). This also enforces CLAUDE.md's "polling MUST stop on `game_state === 6`" pitfall.
- BFF cache TTL for the new route: `TTL.DRAFT = 4` seconds (one second below client poll cadence, guaranteeing each client poll sees fresh upstream data).
- `useMatchDetail` stays on plain `refetchInterval: 30_000` (with `false` on game over). The two hooks compose on `MatchPage` via TanStack Query's default cache keyed by endpoint URL — no cross-contamination.
- Staleness: within the 5s draft cadence, users see new picks/bans within ~5s of the Valve upstream observing them (upstream itself has inherent ~2 min stream delay per MATCH-04 disclosure — already surfaced in ScoreHeader).

### State Transitions

| Transition | Visual behaviour |
|-----------|-----------------|
| Draft starts (`game_state` → 2) and `scoreboard` arrives | DraftSection mounts immediately on the next render after the first successful fetch. No animation — the section just appears. This matches the rest of the app's "no mount animation" aesthetic. |
| A new pick or ban is recorded | The corresponding placeholder slot swaps its content to a rendered portrait. 160ms CSS `transition: opacity 160ms ease, background 160ms ease` on the `DraftPortrait` wrapper makes the swap feel smooth but not distracting. No scale/bounce animation. |
| Active team changes (turn moves from Radiant to Dire) | Glow border transitions `160ms` on Dire column; Radiant glow fades in same duration. Turn indicator text swaps color + copy. Transitions use the same timing + easing as MatchRow hover (established pattern). |
| Tentative ↔ confident (inference flips) | Border style transitions from solid → dashed (no CSS transition for `border-style` works across browsers — this will snap, acceptable). Shadow alpha transitions in 160ms. Text opacity transitions 160ms. |
| Draft ends (`game_state` → 5) | Turn indicator un-renders. Active column glow fades out (160ms). Picks/bans stay on screen, frozen. |
| Match ends (`game_state` → 6) | Same as draft-end, but additionally: if Valve drops `scoreboard` from the payload, the section un-mounts (D-11 accepts this). |

### Accessibility

Desktop-first per REQUIREMENTS.md. Minimum accessibility practice:

- Portrait `<img>` elements: `alt={heroInfo.name}` for picks and bans; empty slots render as `<div>` with no alt attribute (not interactive, not an image).
- Ban X overlay: `<svg aria-hidden="true">` — redundant with the hero portrait `alt`; the ban semantic is conveyed by the visual overlay AND by the row (bans row vs picks row) AND by the tabular layout. Screen readers can't distinguish picks from bans without an explicit label; out of Phase 4 scope (DRAFT-02 is an "at a glance" visual requirement).
- Turn indicator: plain `<p>` text — screen readers will announce `Radiant — picking` verbatim on update. No `aria-live` region (polling causes frequent updates; announcing every 5s would be noisy).
- Active-column glow: conveyed by (a) color border, (b) background tint, AND (c) the text label. Not color-alone.
- No keyboard-interactive elements in `DraftSection` — nothing to tab to, no focus states needed.

### No User Actions

Draft section is read-only. No buttons, no dropdowns, no confirmation dialogs. No destructive actions.

## Copywriting Contract

Every copy string that can appear in the Phase 4 UI is declared here.

| Element | Copy |
|---------|------|
| Radiant column group label | `Radiant` |
| Dire column group label | `Dire` |
| Turn indicator — Radiant picking (confident) | `Radiant — picking` |
| Turn indicator — Radiant banning (confident) | `Radiant — banning` |
| Turn indicator — Dire picking (confident) | `Dire — picking` |
| Turn indicator — Dire banning (confident) | `Dire — banning` |
| Turn indicator — tentative (D-08) | append trailing ` ?` to any confident label, e.g. `Radiant — banning ?` |
| Turn indicator — no guess (inference returned null, but draft is active) | `Draft in progress` |
| Empty pick slot | (no text — bordered placeholder only) |
| Empty ban slot | (no text — bordered placeholder only) |
| Filled pick portrait | hero name via `alt` attribute only; no visible text |
| Filled ban portrait | hero name via `alt` attribute only; no visible text; X overlay is decorative (`aria-hidden`) |
| Section heading | (no visible section heading — the column group labels `Radiant` / `Dire` serve this role, matching HeroPlayerGrid) |
| Error state | (no visible copy — section un-mounts silently on hook error) |
| Loading state | (no visible copy — empty placeholder grid IS the loading affordance) |
| Deferred state (game_state !== 2, scoreboard still present) | (turn indicator hidden; no replacement copy) |

**No primary CTA** — the draft screen is observational, not actionable.
**No empty-state copy** — empty-slot grid is sufficient; adding "Draft starting soon..." would be noise.
**No error copy** — draft failures are silent by design.
**No destructive actions** — no confirmation copy needed.

Copy style rules (carried forward from Phase 2/3):

- Em dashes (`—`) not hyphens (`-`) in the turn indicator separator.
- Trailing space before `?` in tentative labels (`Dire — banning ?` not `Dire — banning?`) so the glyph reads as a separate uncertainty marker rather than a question.
- Sentence case for the "Draft in progress" fallback (not ALL CAPS — let the `uppercase` CSS transform handle casing).
